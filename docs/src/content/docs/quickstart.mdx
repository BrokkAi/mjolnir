This walkthrough takes a fresh installation from its first launch to a running agent session. Start in the repository you want Mjolnir to recognize:

```sh
cd path/to/your/repository
mj
```

## 1. Open your first prompt

When no workspace exists, Mjolnir creates one using the current directory's
name. An empty workspace starts a session automatically and focuses the prompt.
On Linux and macOS, a fresh configuration uses your Codex home (`CODEX_HOME` or
`~/.codex`). If you already have profiles, Codex is preferred; otherwise Mjolnir
uses the first configured profile.

Startup checks for usable Podman, then Docker, and finally uses a local directory
session. Containers start from your current Git repository, including its
uncommitted contents. Plain directories use the local target. You can change the
agent and target with `[startup] profile` and `target` in
[configuration](/configuration/#first-session-defaults-startup).

Launch progress and failures appear on the dashboard. Once ready, type a prompt
and press `Enter`. Existing workspace selection and live-session startup retain
their current behavior. Windows retains guided setup for its supported targets.
Use `mj setup` explicitly when you want guided discovery of other environments.

The normal dashboard then opens. Its session list, Conversation and Prompt regions, target capacity, and profile quota stay visible together.

## 2. Resolve any missing prerequisites

If the first session reports a prerequisite failure, detach with `Alt+Q`, then run:

```sh
mj doctor
```

For machine-readable output, use:

```sh
mj doctor --json
```

Fix errors until the relevant profiles and targets report ready. If a harness profile needs authentication, run:

```sh
mj login --profile <profile-id>
```

Claude Code profiles can use the long-lived setup-token flow:

```sh
mj login --profile <profile-id> --setup-token
```

The login command is profile-aware: it runs the correct harness authentication flow and stores credentials in that profile's home. See [profiles](/profiles/) for isolation and authentication details, or [troubleshooting](/troubleshooting/) if `doctor` still reports a failure.

## 3. Create a custom session (optional)

For another agent, project, or target, press `Alt+W` from anywhere on the dashboard. The new-session wizard walks through:

1. A harness profile.
2. A target on which the session will run, including its resource size when that target is resizable.
3. A project bundle, or an absolute project directory for a bare target.
4. A final review, where supported targets can also receive attached directories.

Press `Enter` to confirm. Mjolnir provisions the selected target in the background, starts the harness, and returns focus to the Prompt pane when the session is ready. The Sessions pane shows launch progress and reports failures instead of freezing the interface.

See [sessions](/sessions/) for lifecycle and persistence, and [targets](/targets/) for the differences between local, container, SSH, and EC2 execution.

## 4. Send the first prompt

Type a message in the Prompt pane and press `Enter`. While the harness is working you can type another message and press `Enter` to queue it. Press `Esc` to cancel the active turn without stopping the session.

Useful controls for the first run:

| Key | Action |
| --- | --- |
| `Tab` / `Shift+Tab` | Move through Sessions, Prompt, Targets, and Quota |
| `Page Up` / `Page Down` | Scroll the transcript from any focus |
| `F1` | Open contextual help |
| `F2` | Open the searchable command palette |
| `Alt+N` | Immediately create another session with saved defaults |
| `Alt+W` | Open the full creation wizard |
| `F4` | Edit configuration in Setup |
| `Alt+Q` | Detach this terminal |

The [terminal surface guide](/terminal-surface/) covers pane sizing, the full composer keymap, the command palette, and `!` shell commands.

## 5. Detach and reconnect

Press `Alt+Q` when you are ready to leave the terminal. Detaching closes only this dashboard: the daemon and sessions keep running, active turns continue, and queued prompts remain queued.

Reconnect with:

```sh
mj
```

Mjolnir reopens the session in your opened workspace whose agent spoke most recently and places the cursor in its Prompt pane. Other workspaces' sessions remain visible for explicit switching. To reach the same sessions from a browser, print the viewer address and access code with:

```sh
mj daemon status
```

See the [web viewer](/web-viewer/) for browser and phone access. For workspace selection, scripting, daemon operations, and every command-line flag, use the [CLI reference](/cli-reference/).
