One command turns the coding session on your machine into a browser you can
drive from the next room — or, over Tailscale, from anywhere:

```bash
mj server
```

Mjolnir Web is the same session, not a summary of it. It runs with the resolved
team, models, permissions, and subagent configuration the terminal client uses,
and it renders what the TUI renders: streaming turns, file diffs, terminal
output, permission prompts, per-seat token usage, and the independent review
pass. The repository, the agent processes, and the transcripts stay on the host.
The browser is a control surface for that session, not a copy of your code.

## What you can do from a browser

- **Answer permission prompts** with the diff or command in front of you — deny,
  allow once, or always allow.
- **Read the work as it happens**: streaming assistant turns, tool calls, file
  diffs, and terminal output.
- **Start new work**, including in a fresh Git worktree, without touching the
  terminal.
- **Pick up sessions from either side.** Sessions started in the terminal appear
  in the browser; sessions started in the browser record their adapter and model
  so `mj resume` reopens them on the host.
- **Steer the running turn** — send a correction while the agent is working
  to place it in the same FIFO queue the terminal uses, then select **Stop**
  to inject the oldest queued correction into that turn when steering is
  supported.
- **Attach an image** to a prompt, and run the agent's own slash commands: typing
  `/` opens a palette of the commands the connected agent advertises.
- **Install it as an app.** Mjolnir Web ships a web app manifest and service
  worker, so a phone can add it to the home screen and open it standalone.

## Start the server

```bash
mj server
```

Without an explicit hostname or a usable Tailscale node, the server listens on
loopback HTTPS (`127.0.0.1` and `::1`) on port 11921 with a locally generated
certificate. It is then reachable only from the same machine, so it prints no
device-login QR code. On a certificate-capable Tailscale node, detection happens
automatically and the server is reachable over the tailnet; `--hostname` exposes
the server under an explicit name instead. On start, `mj server` prints the URL
to open, the six-digit viewer code, and the viewer session lifetime.

## Choose a port

```bash
mj server --port 9443
```

`--port` moves every listener, the printed viewer URL, and the login QR code to
that port. It applies to automatic Tailscale and explicit `--hostname` mode as
well. The running server records its port next to its certificate and token, so
`mj` sessions on the same machine follow a non-default choice without needing
the flag themselves. Until a server publishes a port, sessions use 11921.

Sign in with that viewer code or a bearer login token; the browser then stores a
signed session cookie. Treat QR codes, login URLs, tokens, cookies, certificate
keys, and downloaded transcripts as secrets.

## From your phone

The phone layout is the whole session, not a cut-down status page. Approve a
write against the diff that produced it, watch the reviewer and subagents work,
and send the next prompt. Add it to the home screen and it opens standalone,
like any other app. A phone reaches the server once it is off loopback — see
[Reach it from another device](#reach-it-from-another-device).

The folder picker browses the workspace roots configured on the server. It also
shows up to six working directories from the most recently used retained
sessions and can search for nested folders across those roots. Recent and search
results are canonicalized against the current roots before they are shown, so
changing the server's workspace configuration does not expose old paths. Broad
searches are capped; refine the query when the picker reports that only the
first matches are shown.

are recognized as Mjolnir's own tools rather than third-party ones.

## Subagents in the browser

Mjolnir Web keeps an actor-level subagent list: one row per background subagent,
running rows first in spawn order, each showing its id, label, latest activity,
and elapsed time, and finished rows marked `✔`, `✘`, or `⊘`. This is more
granular than the terminal's aggregate workflow progress rows.

## Side conversations

When the connected agent supports ephemeral side sessions, the web command
palette exposes `/side` with an optional question. The same transcript stays open
in a visible side mode, but side prompts, replies, and tools are labelled with
the `Side` actor so they cannot be mistaken for main-session history. Use the
**Exit side** action (or send `exit`) to delete the temporary session and return
the composer to the main conversation.

Typing `/` opens the palette of commands the connected agent advertises, so the
list reflects that agent's capabilities rather than a fixed menu — `/side` only
appears on an agent that supports side sessions.

## Status line

Under the chat header the browser mirrors the terminal status line: primary
model and its ACP adapter, reasoning effort, per-seat token totals
(primary/review/subagents), context occupancy when the agent reports it,
provider subscription quota windows (Codex/Claude), and a link to the current
branch's open pull request. The pull-request badge comes from a `git`/`gh` probe
on the session host and refreshes about twice a minute.

bind adapters independently, so a single session-wide figure would silently cover
just the seats that happen to report. `/agents` in the terminal breaks cost down
per seat and per model, where the unpriced seats are visible.

## Archiving sessions

The browser can archive a server-owned session to move it out of the active list
and load or unarchive it later. A live TUI session cannot be archived; exit it in
the terminal first. Archiving changes where the session is listed, not its
retained transcript data.

## Configuration from the browser

`/mjconfig` opens the same configuration editor the terminal uses: team, agent,
reviewer, subagent, and ACP-server settings, plus the session options the
connected adapter exposes. Changes apply to sessions started afterwards, not to
the turn already running.

## Ragnarok, read-only

`/ragnarok <task>` is Mjolnir's model-vs-model arena: several champion models
implement the same task in parallel worktrees, each adversarially reviews a
rival's implementation, and a router agent judges the results and crowns a
winner. While a local `/ragnarok` arena is active, the browser shows its task and
phase, each fighter's model source, status, and vigor, plus the final verdict and
adoption guidance when available. This view is read-only: summoning the arena,
approving `UNLEASH`, choosing between finalists, and publishing a draft pull
request remain local TUI actions.

## Reach it from another device

### Tailscale

```bash
mj server
```

`mj server` uses Tailscale when it finds a running tailnet node with MagicDNS and
HTTPS Certificates enabled. Mjolnir then binds to network interfaces, asks
`tailscale cert` for the machine's `ts.net` certificate, and renews it. If it
cannot get a Tailscale certificate, it falls back to loopback. Tailnet
reachability and ACLs are part of the security boundary.

```bash
mj server --no-tailscale-detect
```

`--no-tailscale-detect` keeps the server loopback-only on a tailnet machine.
`--hostname` also skips detection because that hostname is the one the login QR
must point at. The old `--tailscale` flag is accepted as a deprecated no-op.

### Public hostname

```bash
mj server --hostname mj.example.com
```

This binds to network interfaces and generates a self-signed certificate for the
supplied hostname. It does not provision DNS, a trusted public certificate, a
reverse proxy, firewall rules, or internet authentication. Do not expose this
mode directly to an untrusted network without designing those layers.

## Retention and sign-out

```bash
mj server \
  --history-days 7 \
  --session-ttl-days 2
```

- `--history-days 0` keeps disconnected session history indefinitely.
- `--session-ttl-days 0` makes viewer sessions ephemeral.
- `--logout-all` rotates the cookie signing key and signs every viewer out. The
  underlying QR/bearer login token remains available for reauthentication.

Remote state includes local SQLite session/transcript data, queued prompts,
permission decisions, authentication material, and certificates under Mjolnir's
platform state/config directories.

## Before leaving loopback

1. Decide who can reach the server's port (11921 unless `--port` changed it) and
   enforce that with host or tailnet policy.
2. Protect the login token, cookie key, certificates, and transcript storage.
3. Set finite history and session lifetimes.
4. Confirm remote users understand the active workspace and permission mode.
5. Test `--logout-all` and recovery before relying on remote access.
6. Keep the host patched; the server can drive provider agents and answer nested permissions.

See [Data and trust boundaries](/data-boundaries/) and [Storage and network
activity](/storage-network/) for the complete surface.
