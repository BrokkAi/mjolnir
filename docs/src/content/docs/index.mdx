<section class="home-section">
  <p class="section-label">One operating plane</p>
  <h2>Keep every coding session working when you walk away.</h2>
  <p>Mjolnir runs many Codex, Claude Code, Kimi Code, Grok Build, and DeepSeek Harness sessions at once. Prompts queue on the target, sessions survive a closed terminal, and one local daemon coordinates their state, capacity, credentials, and recovery.</p>

        <code>session://durable</code>
      </article>
      <article>
        <small>02 / TARGET</small>
        <h3>Choose the execution boundary</h3>
        <p>Use an existing local or SSH worktree when you need host access, or contain unrestricted work in a container or disposable EC2 instance.</p>
        <code>target://selected</code>
      </article>
      <article>
        <small>03 / CONTROL</small>
        <h3>You keep the whole fleet in view</h3>
        <p>Read live work, queue prompts, watch quota and host capacity, and resume from a verified checkpoint.</p>
        <code>control://local</code>
      </article>

<section class="home-section">
  <p class="section-label">Why Mjolnir</p>
  <h2>Built for more than one agent in one terminal.</h2>
  <p>The control plane becomes useful when sessions outlive terminals, accounts have different quota, or work needs to move between machines without turning every target into a pet server.</p>

    <div class="capability-grid__inner">
      <a href="sessions/">

      </a>
      <a href="targets/">
        <span>02 / EXECUTE</span><h3>Local and remote targets</h3><p>Run locally, in Podman or Docker, over SSH, with Apple container, or on an EC2 instance.</p>
      </a>
      <a href="profiles/">
        <span>03 / CAPACITY</span><h3>Profiles and quota</h3><p>Keep several accounts per harness and see their usable capacity in one consistent view.</p>

      <a href="web-viewer/">
        <span>04 / REMOTE</span><h3>Web and desktop</h3><p>Open the same daemon-owned sessions in a browser, on a phone over Tailscale, or in the native shell.</p>
