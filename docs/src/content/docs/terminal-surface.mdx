The Mjolnir TUI is a single control surface for conversations and the infrastructure behind them. It stays responsive while sessions launch, resume, stop, or run work in the background.

At startup, Mjolnir opens the most recently active live session in the selected
workspace when one is available. When the opened workspace has no live sessions,
the default startup setting creates one from the launch directory once while
the dashboard opens. Set that setting off to leave the workspace empty until
you choose **Create**. Switching workspace tabs only filters the live session
list and never creates a session; every workspace continues running
independently.
Stopped history is available from **Resume**, including sessions that were
previously archived by a provider. Provider archive metadata is read-only.

The Workspace pane has one tab row framed by two borders above Sessions. Click a
tab to switch immediately, or focus Workspaces and use the arrow keys to select
a workspace without opening a manager. The pinned `☰` button at the right of the
tab row opens workspace management for creating, renaming, recovering, or
deleting workspaces. The Workspaces command remains available in the command
palette. The selected workspace also determines where **Create** attaches the
new session.

**Create** opens the full session creation wizard. **Resume** opens all stopped
history, and **Commands** opens the command palette. Commands remains available
while you type and while a notice replaces the footer. Each session row has a
**⋯** button for its actions. Displayed dashboard shortcut hints are clickable,
including global shortcuts in the composer's footer. Help supports wheel
scrolling and a **Close** button.

Open Settings (`prefix+s`) to choose Midnight (the default), Light, Darcula, High
Contrast, or Monochrome. Saving applies the palette to the dashboard, conversation, and dialogs
and preserves it for future launches. Monochrome paints no colors at all and
carries focus and selection with bold and reverse video; setting the
`NO_COLOR` environment variable selects it whatever the configuration says.
**Setup → Advanced → Symbols** switches every status mark, border, chart bar,
and footer separator to plain ASCII for a terminal that cannot show Unicode;
left unset, the dashboard does this by itself on the Linux console or
without a UTF-8 locale. Setup groups the theme, spinner, and
Sessions sidebar position under **Interface**. It also edits Advanced display
options and integrated review settings; see [Configuration](/configuration/).

## Focus and scrolling

`Tab` moves focus through **Workspaces → Sessions → Prompt → Targets → Quota**.
`Shift+Tab` moves in reverse. The transcript is not a tab stop, so focus changes
never take the composer away merely to scroll conversation history. When
Workspaces has focus, `↑` and `↓` select the previous or next workspace tab
immediately; `Enter` opens its manager actions.

Use `Page Up` and `Page Down` to scroll the transcript from any focused pane. A mouse wheel scrolls the surface under the pointer. Clicking a row selects it, and double-clicking a session opens it. Dragging across transcript or pane text copies that surface's selection to the available system or terminal clipboard.

Each list supports the same navigation keys:

| Keys | Action |
| --- | --- |
| `↑` / `↓` or `j` / `k` | Select the previous or next row |
| `Ctrl+P` / `Ctrl+N` | Select the previous or next row |
| `Ctrl+D` / `Ctrl+U` | Move eight rows down or up |
| `Home` / `End` or `G` | Select the first or last row |

These keys work in the support panes, dialogs, and wizards. A focused text
field keeps them as text, so typing `j` or `Ctrl+U` in a search or name field
edits the field instead of moving the selection.

The Sessions pane keeps **Create** and **Resume** above the session list. They
remain available when the list is empty or filtered. Both Create shortcuts open
the full creation wizard; Resume searches every non-live session.

Press `/` in Sessions to search the live list. Typing narrows it to sessions
whose name, project, profile, or target contains the text, and the pane title
shows the query. `Enter` keeps the filter and hands the letters back to the
pane; `Esc` clears the text, and a second `Esc` clears the whole filter. The
letters `b`, `w`, `i`, and `d` keep only blocked (waiting or failed),
working, idle, or done (unread) sessions, `a` shows all again, and a state
filter composes with the search text. Switching workspace clears the filter,
and so does jumping with `prefix+o` to a session the filter would hide.

Normal session rows use four lines: the session name, one metadata line, and
two wrapped output lines. The metadata keeps the profile, target, and useful
status details together; the output shows the latest reply, tool activity, or
prompt. A minimized Sessions pane uses two lines per row, retaining the status
and queue count in the compact form.

The metadata line also carries the checkout's branch once it has been read,
as `⎇ feature/x ↑1 ↓2 ±4`: the branch, commits ahead of and behind its
upstream, and the number of changed files. Mjolnir reads a visible live
session's checkout on its target about once a minute, so the branch is right
even after the agent switches branches. `prefix+d` opens the full list for
the selected session: each file with its kind and its added and removed
lines, `r` or **Refresh** to read again, and `Esc` to close.

Terminal scrollbars are intentionally slim. The transcript, list panes, and
dialogs keep their scrollbar rails for mouse and keyboard scrolling without
letting the rail take space from the content.

Pane-specific actions are deliberately small:

| Focus | Key | Action |
| --- | --- | --- |
| Sessions | `Enter` | Open the selected session |
| Workspaces | `↑` / `↓` | Select the previous or next workspace tab immediately |
| Sessions | `n` / `N` | Open the full session creation wizard |
| Sessions | `Space` | Fold or unfold the selected project |
| Sessions | `1`–`9` | Fold or unfold the numbered project |
| Sessions | `/` | Search sessions by name, project, profile, or target |
| Sessions | `b` / `w` / `i` / `d` / `a` | Show only blocked, working, idle, or done sessions, or all |
| Sessions | `Esc` | Clear the search text, then the whole filter |
| Targets | `Enter` or `e` | Open target actions, including test and rename |
| Quota | `Enter` or `e` | Edit the selected profile configuration ID |

## Pane sizes

The bordered Workspaces and Sessions sidebar is 20 columns wide when minimized.
At standard size it uses one third of the terminal width, bounded to 40–80
columns; maximized uses half, bounded to 40–100 columns. Both stay within half
the terminal on narrow screens. The Workspaces pane keeps one bordered tab row
above the Sessions list at every sidebar size. Sessions, Targets, and Quota each
have minimized (`▁`), standard (`▪`), and maximized (`□`) title-bar controls.
Click a control, or focus a support pane and press `prefix+z` to cycle through
its sizes. Max is hidden when it adds no space over Standard. The sidebar
needs at least 80 columns, so standard and maximized are both 40 columns at
that width.

- A minimized Targets or Quota pane becomes a one-line summary.
- A minimized sidebar narrows the workspace tabs and shows two lines per session.
- Only one support pane can be maximized at a time.
- Maximized Sessions widens the sidebar. Maximized Targets or Quota receives available vertical space below Prompt.

Targets and Quota stay together. When both full tables fit beside a maximized sidebar, they appear below the conversation. Otherwise, they move below both Sessions and the conversation and span the terminal width. Quota retains exact percentages and reset times.

Between 60 and 79 columns, such as a phone over SSH, there is no room for a sidebar: the workspace tabs and a compact Sessions list stack above the conversation, Targets and Quota become one summary row each below it, and every key and click works as before. Below 60 columns the dashboard shows what size it needs instead.

`prefix+b` toggles a dashboard preset. When all panes are standard, it minimizes Sessions, Targets, and Quota. When sizes have been customized, it restores all three to standard. `Tab` changes only focus and never changes a pane's size.

## Conversation panes

The conversation area can hold more than one conversation at a time. Open a
session row's **⋯** menu and choose **Open in split right** or **Open in split
below**. The area divides in two, the chosen session opens in the new pane, and
the keyboard moves there. Selecting a row already moves that conversation into
the pane you are in, so the split puts it in the new pane and returns the pane
you came from to the conversation it was showing.

Every open conversation keeps running whether or not it is the one you are
typing into, so a pane's transcript advances as its agent replies.

The pane you are typing into is the focused pane. It draws the focused border
and its keys fill the footer. Click any pane to move the keyboard to it. The
Sessions highlight follows the focused pane, so the highlighted row is always
the conversation you are in.

The keys follow herdr and tmux. They run from the composer and from the
Sessions list:

| Key | Action |
| --- | --- |
| `prefix+v` | Split beside: open the selected session to the right |
| `prefix+minus` | Split below: open the selected session underneath |
| `prefix+x` | Close the pane you are in, saving what it held |
| `prefix+h` / `prefix+j` / `prefix+k` / `prefix+l` | Move the keyboard to the pane left, below, above, or right |

`prefix+v` and `prefix+minus` act on the Sessions selection, the same as the
**⋯** menu entries. With nothing selected the new pane is empty and waits for a
session. Closing the last pane empties it rather than removing it.

The command palette (`prefix+:`) carries the same commands plus **Resize pane
left / down / up / right**, which moves the pane's border one step. The resize
commands have no key by default; bind `resize_pane_left` and its three
companions under `[keys]` to give them one.

A split is refused when either half would be under 40 columns or 8 rows; the
dashboard says "Not enough room to split" and nothing changes. Pressing `Enter`
on a session that another pane already shows moves the keyboard to that pane
instead of opening a second copy.

The arrangement is saved per workspace, so the panes, their sessions, and which
pane had the keyboard come back when you restart `mj` or switch back to that
workspace.

## Prefix key

Mjolnir uses a tmux-style prefix key instead of one direct chord per command: press the prefix, release it, then press a second key. The footer shows a `PREFIX` banner while a prefix press is pending. The default prefix is `ctrl+b`, the same as tmux and [herdr](https://github.com/herdrdev/herdr), so the same muscle memory carries over. `Esc` cancels a pending prefix without sending anything; an unbound key after the prefix shows a footer notice instead of doing nothing silently.

The commands below run from any dashboard pane and from the composer, once the prefix has been pressed. They are written here as `prefix+<key>` because every one of them, including the prefix itself, can be rebound:

| Key | Action |
| --- | --- |
| `prefix+?` | Open help; `?` also opens it when a non-Prompt pane has focus |
| `prefix+:` | Open the command palette |
| `prefix+s` | Open Settings |
| `prefix+c` | Open the full session creation wizard |
| `prefix+g` | Resume any non-live session through the resume picker |
| `prefix+shift+n` | Open workspace management |
| `prefix+w` | Focus the workspace tab row |
| `prefix+n` / `prefix+p` | Select the next or previous workspace |
| `prefix+1`–`prefix+9` | Select a workspace by number |
| `prefix+tab` | Focus the next support pane |
| `prefix+shift+tab` | Focus the previous support pane |
| `prefix+z` | Cycle the focused support pane's size |
| `prefix+b` | Toggle the dashboard pane preset |
| `prefix+shift+r` | Refresh all target capacity and profile quota data |
| `prefix+shift+c` | Cancel the selected session's in-flight launch, resume, or stop operation |
| `prefix+a` | Mark all session activity as read |
| `prefix+o` / `prefix+shift+o` | Open the next or previous session that needs you, in any workspace |
| `prefix+u` | Show the web viewer address and access code |
| `prefix+shift+t` | Rename the selected session |
| `prefix+t` | Toggle the transcript between rendered and raw text |
| `prefix+d` | List the selected session's changed files, branch, and distance from upstream |
| `prefix+m` | Start or stop dictation when voice input is available |
| `prefix+v` | Open the selected session in a pane beside this one |
| `prefix+minus` | Open the selected session in a pane below this one |
| `prefix+x` | Close the conversation pane you are in |
| `prefix+h` / `prefix+j` / `prefix+k` / `prefix+l` | Move the keyboard to the conversation pane left, below, above, or right |
| `prefix+q` | Detach this terminal while the daemon and sessions continue |

`Esc` is not a detach key. It closes a dialog or, from the conversation, cancels the active agent turn or shell command. `prefix+shift+c` is different: it cancels a lifecycle operation such as launch or resume. Stop, Restart, Move, Delete session, container settings, and managing profiles or targets have no default key; run them from the command palette so a mis-hit key cannot act on a live session.

Pressing the prefix twice sends the literal key through to whatever has focus instead of running a command. In the composer this is how you still reach `Ctrl-B`, backward-character: press `ctrl+b ctrl+b`.

Every binding above, including the prefix itself, is editable in `config.toml` under `[keys]`; see [Configuration](/configuration/#keys-keys).

## Sessions that need you

Every session has an attention level: waiting for your input, failed, unread,
working, or idle. `prefix+o` opens the session that most needs a person and
`prefix+shift+o` walks the same list backwards. Questions come first, then
failures and unreachable sessions, then finished answers you have not read;
within a level the most recent activity leads. The walk continues from the
selected session when it is in the list, wraps at either end, and crosses
workspace tabs, unfolding a folded project on the way. When nothing is
waiting, the footer says so. While something is, the footer names the key
with the count, for example `o next (2)`.

Each workspace tab carries the same count: `!2` for two sessions waiting or
failed, or `✓3` for three unread sessions when none is waiting. A folded
project heading carries the count for its hidden rows.

When a session you are not looking at starts needing you, Mjolnir rings the
terminal bell after a short delay and keeps the terminal window title at
`mj · 2 waiting · 1 unread`, so a background tab or a tmux window shows the
count without switching to it. **Setup → Notifications** turns the bell off,
adds a desktop notification, or changes the delay; see
[Configuration](/configuration/#notifications-notify).

**Setup → Advanced → Session order** changes how the Sessions pane sorts.
`project` (the default) groups sessions under a heading per project in
creation order. `priority` drops the headings and lists sessions by attention
level, so a question is always at the top; the numbered fold keys do nothing
in this order.

## Command palette

Click **Commands** or press `prefix+:` to expose both shortcut-backed and palette-only actions. Commands for the selected session come first, followed by commands for the focused pane and then global commands. Click a command and **Run** to execute it, or **Close** to dismiss the palette. A session row's **⋯** button opens a palette limited to that session's actions.

Matching is fuzzy: `cre` finds **Create session** and `mvs` finds **Move session**, with a command whose label starts with the query first, then in-order matches on the label, then commands whose description contains the text. With an empty query the last five commands you ran appear under **Recent** before the groups. Create, Resume, and Workspaces are listed like every other command, so a search finds them even though they also have buttons.

Use `↑` / `↓` or `Ctrl+P` / `Ctrl+N` to select a command, `Enter` to run it, and `Esc` to close the palette. Selected-session actions include Rename session, Container settings for container-backed sessions, Move, Stop, Restart, and Delete. Stop, Restart, Move, and Delete have no keyboard shortcut: they are available from the palette and from a session row's **⋯** menu only, so a mis-hit key cannot stop a live session. **Move** opens a preparation and confirmation flow for a compatible profile or target; it keeps the logical session while rebuilding a fresh environment. Stop and Restart run at once on an idle session and ask first when the agent is mid-turn, since that is when a mis-click costs work; Stop also retries a stop that failed part-way without asking. Delete permanently removes the session, its target, and its recovery archive after a confirmation. Every confirmation lists a letter for each button under its text, for example `n No · y Yes · d Yes, delete branch`, so no confirmation needs Tab; `Esc` always takes the safe answer. The palette is also how you discover useful commands that have no dedicated key.

## New session and Setup

Press **Create**, `n`, `N`, or `prefix+c` to open the full session
creation wizard. It asks for the profile, project, target, and launch options,
then provisions the session in the selected workspace. The new row appears
immediately with background launch progress; when it is ready, the normal Prompt
receives focus. No separate fast path or task-entry dialog remains.

Press `prefix+s` to edit all configuration in Settings: accounts, targets and remote
machines, projects, Interface settings (sidebar position, activity animation,
and theme), Advanced display options, review, and web access. Enter opens a
section or edits a value. Fixed choices open in a compact menu over the page;
free-text values open the full editor.
The page's controls stack in a column at its right edge. **Add** and **Remove**
manage entries, and on Projects **Create** makes a new project bundle.
**Detect machine** on **Agent Profiles** discovers the agents installed
on this machine and usable local runtimes. Review settings are part of the same
draft: discovery checks the selected reviewer profile's model and effort
capabilities and filters incompatible profiles. **Save and Close** or Ctrl+S
validates and saves the complete draft. Errors keep your edits in place. `Esc`
cancels an open choice menu; otherwise `Esc`, the title-bar `×`, or Cancel
closes Setup and discards unsaved Setup and review edits. Web listener changes
take effect on its next start.

Detailed activity clocks are off by default. Turn them on in **Setup → Advanced
→ Detailed activity clocks** when you want normal session rows and the
conversation header to show separate turn, step, and background clocks. The
ordinary **Running** status covers the originating turn and its follow-on
background work continuously, so it does not reset or go idle between phases.
The configured spinner appears in the Prompt composer's upper-right corner only
while the selected session is actually busy; an idle or stopped session does
not animate.

Stopped sessions are hidden from the Sessions pane by default and remain
available through **Resume**. Enable **Setup → Advanced → Show stopped sessions**
to include them in the Sessions pane for their workspace.

## Prompt editor

The Prompt pane is a multiline editor with completion, history, and transcript
controls. A `>` marks the editable input. The microphone button occupies the
upper-left corner of the composer, followed by **Model** and **Effort**. The
selected session's busy spinner appears at the upper right while work is active.
It disappears when the session is idle, stopped, or waiting without active work.

The bottom border contains **View tasks (N)**. With the cursor on the last input
line, press `↓` to focus that control; press `Enter` to open the tasks dialog and
`Esc` to close it. The dialog lists the session's queued and active tasks without
changing the prompt draft.

| Key | Action |
| --- | --- |
| `Enter` | Send now, or queue while the active turn is running |
| `Shift+Enter` / `Alt+Enter` | Insert a newline |
| `Tab` | Accept a completion, or move to the next pane when none is offered |
| `Esc` | Cancel the running turn or shell command |
| `Page Up` / `Page Down` | Scroll the transcript |
| `↑` / `↓` | Move within multiline input or walk prompt history |
| `Ctrl+R` | Search prompt history; `Alt+R` changes the search scope |
| `Ctrl+V` | Paste the system clipboard |
| `Ctrl+A` / `Ctrl+E` | Move to the start or end of the line |
| `Ctrl+B` / `Ctrl+F` | Move back or forward one character |
| `Alt+B` / `Alt+F` | Move back or forward one word |
| `Ctrl+H` / `Ctrl+D` | Delete before or after the cursor |
| `Ctrl+W` / `Alt+D` | Delete the word before or after the cursor |
| `Ctrl+U` / `Ctrl+K` | Delete to the start or end of the line |
| `Ctrl+Y` | Yank the most recently killed text |
| `Ctrl+C` | Save the current draft to history and clear Prompt |
| `Ctrl+P` / `Ctrl+N` | Move to the previous or next line, then through history |

Inside history search, `Ctrl+R` or `↑` selects an older match, `Ctrl+S` or `↓` selects a newer match, `Enter` accepts it, and `Esc` or `Ctrl+C` cancels the search.

Toggling the transcript between rendered and raw text (`prefix+t`) and starting or stopping dictation (`prefix+m`) are prefix commands rather than composer-only keys; see [Prefix key](#prefix-key). They act on whichever session's conversation is visible, including from a pane other than Prompt.

## Shell commands

Start a message with `!` to run the remainder through `bash -lc` inside the selected session's target and workspace:

```text
!git status --short
```

The command runs independently of an active agent turn, so it does not block the harness. Mjolnir streams bounded live output into the transcript and saves the result there. After the command finishes, its result is included once as hidden context with the next prompt you submit, letting the agent respond to what the command found without copying the output into Prompt.

Press `Esc` to cancel a running shell command. The same `!` syntax works in the [web viewer](/web-viewer/), where a Cancel button replaces the terminal key. A shell command has the permissions of the selected target, so review destructive commands just as you would in a directly attached shell.

## Help, footer, and terminal setup

Press `prefix+?` for scrollable contextual help and `Esc` to close it. The footer is generated from the same command registry: pane-local commands appear first, then the live prefix chord group, so the footer never names a key that is not actually bound.

Inside help, press `/` to filter the rows. Typing narrows them to the rows whose key, command name, or description contains what you typed; `Ctrl+U` clears the filter text; `Esc` clears the filter and a second `Esc` closes help; `Enter` closes it from either state. The arrow and page keys keep scrolling while the filter has focus.

If you run Mjolnir inside tmux or GNU screen with its default `ctrl+b` prefix, the multiplexer sees `ctrl+b` first and Mjolnir's prefix never arms. Press `ctrl+b` twice to send it through, as you would for tmux's own prefix, or set `prefix` to a different key in `[keys]`. The dashboard notices this on its first launch inside a multiplexer and says so once in the footer.

Inside help, `Esc` clears the filter text if there is any and otherwise closes help. On a pane, `Esc` clears the footer notice.

The footer holds one notice at a time. When a second failure arrives before the first has been readable for a few seconds, the bar reads `2 failures · latest: …` so nothing is silently lost, and **Recent messages** in the command palette lists the last thirty notices, newest first, with failures in the warning color.

For session states and recovery behavior, continue to [sessions](/sessions/). The [CLI reference](/cli-reference/) covers non-interactive commands, while [troubleshooting](/troubleshooting/) covers key handling, target failures, and viewer connectivity.
