- [P2] Search every inheritance branch before choosing a member — src/analyzer/usages/get_definition.rs:3032-3034. When one direct base declares a member and another base inherits a member with the same name from a more distant ancestor, this returns only the first declaration. C++ member lookup must also consider the second branch, so an ambiguous reference such as `D : A, B`, where `A::x` and `B` inherits `C::x`, is incorrectly reported as resolved to `A::x`.
- [P2] Resolve base aliases to their underlying class — src/analyzer/usages/get_definition.rs:3023-3025. For `using Alias = Base; class Derived : public Alias {};`, `cpp_direct_base_types` can return the alias unit, but this traversal searches for `Alias.member` and then treats the alias as a class with bases. Consequently inherited members of `Base` are never found, even though the visibility index has an alias-target resolver.
- [P2] Make the inheritance walk stack-safe — src/analyzer/usages/get_definition.rs:3036-3036. A sufficiently deep inheritance chain with no matching member makes one Rust call per class and can overflow the process stack during a definition lookup. The repository explicitly requires iterative analyzer graph walks when depth is not bounded ([AGENTS.md](/workspace/4b864da96d47a89be16b7642723c90b4/bifrost-dev/AGENTS.md:41)).
