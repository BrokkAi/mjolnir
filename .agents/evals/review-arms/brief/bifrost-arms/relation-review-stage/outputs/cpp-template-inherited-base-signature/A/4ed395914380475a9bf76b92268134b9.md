- [P2] Look up inherited members independently along each base branch — src/analyzer/usages/get_definition.rs:3032-3034. With multiple inheritance, finding a member in one direct base stops the search through every other base, even when another branch inherits a different member with the same name. For example, if `D` derives from `A` and `B`, `A` declares `f`, and `B` inherits `f` from `C`, lookup of `D::f` is ambiguous in C++, but this returns only `A::f` as a resolved definition.
- [P2] Give class members precedence over free functions in unqualified calls — src/analyzer/usages/get_definition.rs:2925. When a member function and a visible free function have the same name, filtering the member out here makes the existing free-function lookup return the free function before the enclosing class is searched. Thus `void f(); struct A { void f(); void g() { f(); } };` resolves the call to the global `f` even though C++ selects `A::f`.
- [P2] Traverse inheritance without consuming the call stack — src/analyzer/usages/get_definition.rs:3036. For a sufficiently deep inheritance chain whose classes do not define the requested member, each base adds another Rust stack frame and can overflow the process stack during definition lookup. The repository explicitly requires stack-safe traversal for analyzer graph walks ([AGENTS.md](/workspace/3a8acbe12b3ecb5a6224de083634ed2a/bifrost-dev/AGENTS.md:41)); an explicit work queue avoids making supported hierarchy depth depend on stack size.
