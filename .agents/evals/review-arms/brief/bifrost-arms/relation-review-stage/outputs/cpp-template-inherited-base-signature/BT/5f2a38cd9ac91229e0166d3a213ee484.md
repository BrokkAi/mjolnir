- [P2] Search each inheritance branch independently — src/analyzer/usages/get_definition.rs:3032-3034. When one direct base declares the requested name and another inherits it from a deeper base, stopping at the first populated depth ignores the second branch. For example, if `A` and `C` both declare `x`, `B : C`, and `D : A, B`, lookup of `D::x` is ambiguous, but this returns only `A::x` as resolved.
- [P2] Resolve base names in the declaring class's scope — src/analyzer/usages/get_definition.rs:3023-3023. When multiple namespaces contain classes with the same short name, an unqualified base such as `namespace n { struct Base { int x; }; struct Derived : Base {}; }` is resolved using the query file's first visible `Base`, rather than the namespace of `Derived`. Consequently an unrelated base can be traversed and the wrong member returned, including when the derived class is declared in an included header.
- [P2] Follow type aliases when traversing bases — src/analyzer/usages/get_definition.rs:3023-3025. For `using Alias = Base; struct Derived : Alias {};`, base resolution can return the alias unit itself, but the traversal then searches for `Alias.member` and parses the alias as a class declaration. Members of `Base` are therefore never found through this valid inheritance declaration.
- [P2] Make inherited traversal stack safe — src/analyzer/usages/get_definition.rs:3036-3036. A long inheritance chain with no matching member recurses once per class and can overflow the process stack during a definition query. The repository explicitly requires iterative traversal for analyzer graph walks whose depth is unbounded ([AGENTS.md:41-44](AGENTS.md#L41-L44)).
