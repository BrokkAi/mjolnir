- [P1] Preserve qualified Scala visibility before removing the gap — crates/bifrost-jvm/src/scala/resolution.rs:508-509. Scala visibility facts collapse `private[pkg]`, `protected[pkg]`, and `private[this]` into the same values as unqualified modifiers, but these have different access scopes. For example, a valid `private[pkg]` access from another class in the package is now definitively denied, while `private[this]` can be incorrectly allowed through another instance. Keep these cases incomplete until their qualifiers and receiver restrictions are represented and evaluated.
- [P2] Include companions when evaluating protected access — crates/bifrost-analysis/src/analyzer/store/resolution_operation/java_access.rs:237-242. A Scala companion can access protected members of its companion class, but this branch only tests whether an enclosing template is a subtype of the declaration owner. An access from `object C` to a protected member of `class C` is therefore denied when the object is not itself a subclass, removing a valid resolution target.
- [P2] Mark Scala visibility unresolved when an endpoint is missing — crates/bifrost-analysis/src/analyzer/store/resolution_operation/java_access.rs:255-255. If a reference endpoint is unavailable, including a Kotlin reference because the JVM endpoint reader only reads Java and Scala, this default returns `Unknown` with `visibility_applies` false. Since Scala declarations no longer carry a visibility gap, the caller converts that unknown decision to allowed and can report a complete resolution to a private or protected Scala member without checking access.
