- [P1] Preserve qualified Scala visibility scopes — crates/bifrost-jvm/src/scala/resolution.rs:508-509. For declarations such as `private[pkg] def f`, the source visibility fact collapses the qualifier to `Private`, but the new policy treats that as access limited to the declaring template and its companion. Removing the visibility gap therefore turns valid calls from other code in `pkg` into definite denials; `private[this]` is also incorrectly widened to the entire template and its companion. The qualifier must remain represented or the result remain incomplete.
- [P2] Include companions in Scala protected access — crates/bifrost-analysis/src/analyzer/store/resolution_operation/java_access.rs:237-243. When a Scala companion object accesses a protected member of its companion class, it has the same access rights as the class, but this branch checks only whether the object is a subtype of the class. A normal companion is not a subtype, so the valid access is denied even though the companion relation was already loaded.
- [P1] Read non-Scala JVM caller endpoints for Scala visibility — crates/bifrost-analysis/src/analyzer/store/resolution_typed/java_access.rs:59-60. For a Kotlin reference to a Scala private or protected member, this query excludes the Kotlin reference and the Java endpoint reader excludes it too. The access policy then returns `Unknown` with `visibility_applies` false, so the new gap-free Scala visibility is never enforced and an inaccessible member can be reported as a complete resolution.
