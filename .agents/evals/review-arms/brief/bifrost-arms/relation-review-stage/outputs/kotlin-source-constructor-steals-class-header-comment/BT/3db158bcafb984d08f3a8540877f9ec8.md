- [P1] Preserve executable bodies when narrowing overload ranges — crates/bifrost-analysis/src/analyzer/semantic/workspace_oracle/dispatch.rs:3698-3702. For a TypeScript overload declaration followed by an implementation with the same parameter list, signature selection prefers the implementation, but `selected_callable_layout` chooses the earliest matching range, which is the bodyless declaration. This filter then removes the implementation procedure, so calls that previously had a dispatch target lose their executable target and downstream semantic analysis becomes incomplete.
- [P2] Keep same-named Kotlin methods distinct from constructors — crates/bifrost-jvm/src/kotlin/graph/resolver.rs:244-248. When a class declares a method with the same name as the class, its method and constructor now share the same source `CodeUnit` and accumulate metadata on it. The constructor metadata therefore makes this predicate reject the ordinary method as well, so calls such as `instance.Client()` no longer resolve; the corresponding exclusion in Kotlin definition lookup has the same problem.
