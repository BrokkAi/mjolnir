- [P1] Keep constructor and same-named member identities distinct — crates/bifrost-jvm/src/kotlin/declarations.rs:399-408. A class can declare a member function with the same name as the class, for example `class Client(val x: Int) { fun Client() {} }`. Removing the synthetic distinction makes the constructor and function share one `CodeUnit` and signature set. The new constructor-role filters then exclude the entire unit from ordinary member lookup, so `client.Client()` no longer resolves; constructor binding can also select or report ambiguity against the unrelated function signature.
- [P2] Skip comments when locating Kotlin default expressions — crates/bifrost-jvm/src/kotlin/syntax.rs:495-504. Kotlin permits comments between a parameter and `=` or between `=` and its expression. In `fun f(x: Int /* comment */ = 1)`, the immediate sibling is the comment, so the default is missed; in `fun f(x: Int = /* comment */ 1)`, the comment can be returned as the default. This produces incorrect default binding ranges or missing default rows, and also affects primary-constructor initializer inventory.
