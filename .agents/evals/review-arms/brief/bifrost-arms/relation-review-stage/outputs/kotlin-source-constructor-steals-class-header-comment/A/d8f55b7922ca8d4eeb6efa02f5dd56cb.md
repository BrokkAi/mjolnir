- [P1] Preserve the definition when a C++ prototype precedes it — crates/bifrost-analysis/src/analyzer/semantic/workspace_oracle/dispatch.rs:3698-3701. For a C++ function with a prototype followed by its definition, `selected_callable_range` chooses the earliest matching range, which is the prototype even though signature selection prefers the body entry. This filter then removes the actual procedure because its anchor lies in the later definition, causing dispatch and downstream semantic analysis to lose the function body. The existing `CPP_OVERLOADS` fixture has exactly this declaration layout.
- [P2] Match Kotlin vararg layouts using their declared arity — crates/bifrost-analysis/src/analyzer/usages/call_relations.rs:2408-2413. When a Kotlin overload set includes a `vararg` declaration, the persisted arity marks that parameter optional and repeated, but `is_variadic_parameter` always returns `None` for Kotlin. Consequently no AST layout can match the selected vararg arity, so calls selecting that overload lose their formal bindings and selected body even when arity uniquely identifies it.
