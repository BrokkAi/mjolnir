- [P2] Recognize variadic slots when matching overload ranges — crates/bifrost-analysis/src/analyzer/usages/call_relations.rs:2408-2413. When a Kotlin callable has multiple overloads and the selected overload has a `vararg` parameter, its persisted arity is repeated and excludes the vararg from the required count, but `is_variadic_parameter` currently always returns `None` for Kotlin. Consequently no declaration range matches that arity, so the selected overload loses its formal layout and cannot produce the intended argument bindings, even when its arity uniquely identifies it.
- [P2] Keep same-named methods distinct from constructors — crates/bifrost-jvm/src/kotlin/declarations.rs:405-408. A Kotlin class can declare an ordinary method with the same name as the class; changing its constructor to a non-synthetic `Owner.Owner` function gives both declarations the same CodeUnit identity. Their signature metadata is then combined, and the new constructor-role filters reject the entire unit as a constructor, making calls to the ordinary method unresolvable.
