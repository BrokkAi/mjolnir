- [P2] Preserve same-named methods when excluding constructors — crates/bifrost-jvm/src/kotlin/graph/resolver.rs:244-248. In a class such as `class Foo(x: Int) { fun Foo() {} }`, the constructor and method have the same source `CodeUnit` identity and accumulate signature metadata on that unit. Testing whether any signature is a constructor therefore excludes the ordinary method from member lookup as well, so `foo.Foo()` cannot resolve; the corresponding definition lookup and skeleton filters have the same issue.
- [P2] Skip comments when locating Kotlin parameter defaults — crates/bifrost-jvm/src/kotlin/syntax.rs:496-497. Kotlin permits comments between a parameter's type and `=`, so in `fun f(x: Int /* comment */ = 1)` the immediate sibling is the comment and this returns no default. Consequently a call to `f()` loses its defaulted binding; comments between `=` and the expression can likewise be returned as the default expression by `next_named_sibling()`.
