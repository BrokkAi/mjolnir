- [P1] Invalidate conditional writes when the result is not directly guarded — crates/bifrost-rql/src/structural/search/effects.rs:2677-2678
  When `errors.As(err, &exitError)` has its result discarded or stored before checking, the call is marked as fully modeled, but no edge write is installed because `direct_opaque_guard_edges` cannot find a direct guard. The scalar state therefore retains the pre-call value even though `errors.As` may have changed it, producing an exact nil finding for a successfully populated target or suppressing a finding when the target becomes nil. Invalidate the affected binding when the conditional effect cannot be represented on guard edges.
- [P2] Invalidate mutations through address aliases — crates/bifrost-flow/src/scalar_state.rs:285-289
  When an address is first stored in a local, as in `alias := &value; mutate(alias)`, the argument is a binding rather than an `Address` value, so this check preserves the old fact for `value` even if `mutate` changes it. Subsequent nilness operations can consequently report safe code or miss a real nil dereference; the invalidation needs to follow the structured address origin through local flows.
