- [P1] Respect callable shadowing when identifying constructions — crates/bifrost-analysis/src/analyzer/kotlin/semantic/values.rs:532-541. If a local function or function-valued parameter named `Money` shadows a value class of the same name, `Money(x)` calls that binding, but this lookup still identifies it as the value-class constructor. Lowering then emits a construction transfer from `x` and suppresses ordinary call-result semantics, producing false value and identity facts. The existing `names_constructible_class` check already accounts for these shadowing bindings.
- [P2] Account for unboxing in inferred non-null bindings — crates/bifrost-analysis/src/analyzer/kotlin/semantic/values.rs:518-525. For `val x = boxed!!` where `boxed` has type `Money?`, the non-null assertion yields the unboxed `Money` carrier, but unwrapping the expression here retains the boxed carrier and an inferred declaration emits no adaptation. Subsequent uses such as `val y: Money? = x` therefore also omit the required boxing and incorrectly treat the two bindings as sharing the same carrier.
