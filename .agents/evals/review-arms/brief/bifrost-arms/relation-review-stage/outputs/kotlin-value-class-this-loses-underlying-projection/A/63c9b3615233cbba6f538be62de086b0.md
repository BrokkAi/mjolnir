- [P1] Resolve the callable before treating a call as a constructor — crates/bifrost-analysis/src/analyzer/kotlin/semantic/values.rs:532-541. A function or callable variable can share a value class's name, for example `value class Money(val n: Long)` alongside `fun Money(s: String): String`; `Money("x")` then calls the function, but this lookup classifies it as a value-class construction. Lowering consequently emits a construction transfer from the string argument and propagates a fictitious `Money` carrier into later bindings and projections.
- [P1] Resolve written type names in their lexical scope — crates/bifrost-jvm/src/kotlin/value_classes.rs:593-595. The declarations map is keyed only by simple name, so a nested value class is treated as the meaning of that name everywhere in the file. For example, with `class Outer { @JvmInline value class Money(val raw: Long) }` and an imported unrelated `Money`, a parameter typed `Money` outside `Outer` is classified as the nested value class; reading its `raw` property then replaces a real field load with an unboxing transfer. The same lookup also misclassifies member destinations.
