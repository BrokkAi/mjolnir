- [P1] Respect callable shadowing when identifying constructors — crates/bifrost-analysis/src/analyzer/kotlin/semantic/values.rs:532-541. When a local function, parameter, or callable binding has the same name as a value class, a call such as `Money(raw)` can invoke that binding rather than the constructor. This lookup uses only the spelling and still emits the value-class construction transfer, attributing the call result to its argument and suppressing normal allocation behavior even though the existing `names_constructible_class` check explicitly rejects these shadowed calls.
- [P2] Resolve written type names in their lexical scope — crates/bifrost-jvm/src/kotlin/value_classes.rs:593-596. If a file declares `Outer.Money` and imports a different `Money`, a type annotation `Money` outside `Outer` denotes the import, but this file-wide simple-name lookup classifies it as `Outer.Money`. Parameters and locals of the imported type consequently receive false value-class carriers and can produce incorrect boxing transfers and underlying-property projections. The declaration's scope and import binding need to be considered before claiming its identity.
- [P2] Separate storage for incomplete adaptations — crates/bifrost-analysis/src/analyzer/kotlin/semantic/values.rs:790-792. When a known value class is stored in a member whose type is outside the file, or returned to an unproven written destination, returning the original source makes the subsequent store or return ordinary identity-preserving flow. The destination may actually require boxing, so the gap does not prevent identity consumers from observing a false alias; the incomplete adaptation needs its own destination and language-defined flow, as it does for binding assignments.
