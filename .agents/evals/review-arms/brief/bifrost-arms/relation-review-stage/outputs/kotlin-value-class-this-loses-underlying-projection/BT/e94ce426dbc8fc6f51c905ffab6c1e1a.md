- [P1] Respect callable shadowing when identifying constructors — crates/bifrost-analysis/src/analyzer/kotlin/semantic/values.rs:532-541
  When a parameter, local function, or local variable named `Money` shadows a value class of that name, a call such as `Money(raw)` invokes that callable, but this lookup still classifies it as a value-class constructor. The lowerer then emits a preserving transfer from the argument to the result and suppresses the ordinary allocation handling, producing false value and identity facts for a valid call. The existing `names_constructible_class` check already accounts for these bindings.
- [P1] Resolve written type names in their actual scope — crates/bifrost-jvm/src/kotlin/value_classes.rs:589-598
  When a file declares a value class `Money` but a written `Money` type resolves to a different declaration, for example through an explicit import or a nearer nested type, this simple-name lookup nevertheless identifies the local value class. Parameters and destinations then receive incorrect carrier types, so ordinary property reads can be replaced by unboxing and assignments can gain false boxing transfers. The declaration's identity must be resolved at the type's scope before claiming a carrier.
