- [P1] Resolve a call before treating it as a value-class constructor — crates/bifrost-analysis/src/analyzer/kotlin/semantic/values.rs:532-541. A simple callee name can resolve to a function or a local callable rather than the class constructor, for example an overload `fun Money(s: String): String` alongside `value class Money(val amount: Long)`. Calling `Money("x")` is then modelled as a value-class construction, producing a false carrier conversion and suppressing the ordinary call-result semantics. Resolve the callable identity before asserting that it constructs the indexed class.
- [P1] Resolve written type names in their lexical scope — crates/bifrost-jvm/src/kotlin/value_classes.rs:593-595. The index contains nested declarations from the whole file, but this lookup uses only their simple names. For example, if `Outer` declares a nested value class `Money` and another function imports and uses a different `Money`, the imported type is classified as `Outer.Money` even though the nested declaration is not in scope. This can generate false boxing and unboxing transfers and replace real property reads with underlying-value projections; the written type needs the same scope-aware declaration resolution used for annotation identities.
