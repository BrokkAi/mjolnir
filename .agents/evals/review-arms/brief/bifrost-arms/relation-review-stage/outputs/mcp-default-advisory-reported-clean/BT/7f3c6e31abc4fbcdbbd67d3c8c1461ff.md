- [P1] Preserve exhaustive validation before replacing a baseline — crates/bifrost-policy/src/coordinator.rs:209-210. When `--accept-current` encounters an inconclusive policy, classifying it as clean now lets the existing baseline-writing path overwrite the baseline with only the findings discovered by the partial run. Previously this path refused to write; findings missed during the incomplete evaluation can consequently lose their accepted status when they reappear. Baseline acceptance needs its own exhaustive-completion check rather than relying on the newly relaxed exit status.
- [P2] Expose the strict inconclusive option on scan — src/bin/bifrost.rs:1884. `bifrost scan` always constructs the default `Pass` option, and its separate argument parser does not accept `--on-inconclusive`, so users of this entry point cannot restore the previous exit-2 behavior. This also makes the documented instruction to pass `--on-inconclusive unreliable` for a scan unusable.
