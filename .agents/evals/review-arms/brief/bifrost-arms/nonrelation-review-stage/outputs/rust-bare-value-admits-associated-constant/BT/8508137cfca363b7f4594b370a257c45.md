- [P2] Include callable constants and statics in call lookup — src/analyzer/usages/get_definition/rust.rs:899-902
  When a function pointer is stored in a module-level `const` or `static`, as in `const HANDLER: fn() = handler; HANDLER();`, the callee is classified as `Callable` but this predicate rejects its declaration. Definition lookup and signature targeting consequently lose a valid indexed definition, and an explicitly imported constant is incorrectly reported as an unindexed boundary.
- [P2] Stop generic parameter visibility at nested item boundaries — src/analyzer/usages/get_definition/rust.rs:483-487
  A nested item cannot capture its enclosing function's type parameters, but this walk continues through that item into the outer function. For example, with a module-level `struct T` and `fn outer<T>() { fn inner(_: T) {} }`, lookup on `inner`'s `T` reports a local type parameter instead of the module-level type.
- [P2] Resolve lexically inherited macro_rules definitions — src/analyzer/usages/get_definition/rust.rs:635-644
  A `macro_rules!` declaration is visible textually in child modules declared after it, including child modules in other files. An unqualified invocation in such a child has no import binder, but this lookup only searches the current file and module, so it returns `no_definition` for the valid parent macro and prevents downstream reference and rename operations from finding it.
