- [P1] Keep member candidates tied to the receiver's source file — src/analyzer/usages/get_definition.rs:994-995 — When two directories contain files with the same basename and the same object/property names, their declarations have identical FQNs. This global lookup returns properties from both files even when the receiver was resolved to one specific file, so a definition request can report the wrong file or become ambiguous.
- [P2] Resolve the actual function before inferring its return shape — src/analyzer/typescript/mod.rs:1036-1040 — When another scope contains a same-named identity function, this whole-file search treats that unrelated function as the callee. For example, a local `function wrap(x) { return x; }` inside another function causes a top-level `wrap({a: 1})` call to be indexed as having `a` even if the top-level `wrap` returns something else. The resulting property definitions and skeleton are incorrect.
- [P2] Do not infer preservation from just one return path — src/analyzer/typescript/mod.rs:1152-1154 — For a function such as `function wrap(x) { if (flag) return x; return {}; }`, finding the first matching return marks every call as shape-preserving, although the returned value can lack all of the indexed properties. The same problem occurs when a spread result overwrites an input property after the spread.
- [P2] Avoid treating z.object's argument as the returned object's properties — src/analyzer/typescript/mod.rs:1000-1002 — For the common Zod call `const schema = z.object({name: z.string()})`, the result is a schema object and `name` belongs to its shape, not to the schema itself. Indexing `schema.name` as the argument property produces a false definition; the spelling check also matches unrelated objects named `z`.
- [P2] Make the full-file function search stack-safe — src/analyzer/typescript/mod.rs:1075-1077 — A call with an object argument causes this recursive walk of the entire TypeScript AST, so a sufficiently deeply nested file can overflow the process stack during analyzer initialization. The repository explicitly requires iterative traversal for analyzer walks that can encounter deeply nested ASTs ([AGENTS.md:41](AGENTS.md#L41)).
