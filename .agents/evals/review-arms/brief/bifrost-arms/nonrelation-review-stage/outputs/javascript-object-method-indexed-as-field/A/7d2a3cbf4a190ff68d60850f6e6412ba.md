- [P1] Make the function search stack-safe — src/analyzer/typescript/mod.rs:1075-1077. A TypeScript file containing an object-literal call argument and a deeply nested expression anywhere in the file makes this traversal recurse through the entire syntax tree during declaration collection; sufficiently deep input can overflow the stack and terminate workspace initialization. The same applies to the recursive return-statement walk. The project explicitly requires stack-safe analyzer tree walks ([AGENTS.md:41-44](AGENTS.md#L41-L44)).
- [P2] Resolve the called function in its lexical scope — src/analyzer/typescript/mod.rs:1036-1040. When unrelated scopes contain functions with the same name, any shape-preserving function in the file causes the call to be treated as shape-preserving, even if it invokes a different function. For example, a nested `function wrap(x) { return x; }` makes a top-level `const result = wrap({foo: 1})` acquire `result.foo` even when the top-level `wrap` returns an unrelated value, producing false definitions.
- [P2] Do not treat z.object as returning its argument shape — src/analyzer/typescript/mod.rs:998-999. For a Zod schema such as `const schema = z.object({name: z.string()})`, the call returns a schema object whose `name` field is not the supplied schema property; nevertheless this indexes `schema.name` and resolves references to the argument. The check also matches any unrelated local object named `z`, regardless of its implementation.
- [P2] Avoid rescanning the complete file for every call — src/analyzer/typescript/mod.rs:1036-1038. In a file with many variable initializers such as `const x = factory({ ... })`, every call with an object argument walks the entire AST to search for a matching function, so declaration collection becomes quadratic in file size even when `factory` is imported or absent. Large generated or configuration-heavy TypeScript files can therefore make workspace initialization disproportionately slow.
- [P2] Respect receiver shadowing when resolving members — src/analyzer/usages/get_definition.rs:814-820. If a function parameter or local binding shadows a file-level object, such as `const config = {port: 1}; function f(config) { return config.port; }`, this file-wide lookup resolves the parameter's `port` to the unrelated top-level property. The same issue occurs when a local binding shadows an imported object, because the import branch is selected without considering the reference scope.
