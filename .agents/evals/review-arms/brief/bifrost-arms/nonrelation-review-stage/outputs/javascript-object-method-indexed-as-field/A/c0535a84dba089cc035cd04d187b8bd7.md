- [P1] Traverse function candidates without recursive descent — src/analyzer/typescript/mod.rs:1075-1077. When a TypeScript file contains a call with an object-literal argument, this walks the entire syntax tree recursively during declaration collection. A sufficiently deeply nested expression anywhere in that file can overflow the Rust thread stack and abort workspace initialization. The repository explicitly requires stack-safe traversal for this path ([AGENTS.md](/workspace/b31b9d07eb1205dddfa7ba6031f333b5/bifrost-dev/AGENTS.md:41)).
- [P2] Do not treat Zod schema keys as direct object properties — src/analyzer/typescript/mod.rs:998-999. For `const schema = z.object({ name: z.string() })`, the resulting value is a Zod schema, and `name` is not a direct property of `schema`. Indexing `schema.name` as a definition consequently makes definition lookup report a nonexistent member; the textual `z.object` check also applies to unrelated objects named `z`.
- [P2] Resolve the called function in its lexical scope — src/analyzer/typescript/mod.rs:1036-1040. When an unrelated nested function shares the callee's name and returns its parameter, this whole-file search treats the actual call as shape-preserving even if the function being called returns something else. For example, an inner `function wrap(x) { return x; }` causes a call to a different top-level `wrap` that returns a number to acquire fictitious properties from its argument.
- [P2] Avoid rescanning the entire file for every object argument — src/analyzer/typescript/mod.rs:1036-1038. Each variable initialized by an identifier call with an object argument traverses the complete file to find matching functions. Files containing many such declarations therefore take quadratic time to index, even when none of the callees is defined in the file, which can significantly delay workspace initialization.
