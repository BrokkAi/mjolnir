- [P1] Avoid recursive traversal of the entire TypeScript syntax tree — src/analyzer/typescript/mod.rs:1075-1077 — A top-level call with an object argument causes this walk to descend through every named node in the file. A sufficiently deeply nested expression anywhere in that file can overflow the Rust stack and abort workspace initialization, even when unrelated to the call. The repository explicitly requires stack-safe traversal for declaration collection ([AGENTS.md](/workspace/74fd1136bb880b03c84f4e1c2243e472/bifrost-dev/AGENTS.md:41)).
- [P2] Resolve the called function in its lexical scope — src/analyzer/typescript/mod.rs:1036-1040 — When an unrelated nested function has the same name as the actual callee, `any` treats that nested function as evidence for the top-level call. For example, a non-identity top-level `wrap` and an identity `wrap` inside another function cause `const result = wrap({foo: 1})` to be indexed as having `result.foo`, even though the called function need not return that property.
- [P2] Do not treat z.object as returning its argument — src/analyzer/typescript/mod.rs:998-999 — For the usual Zod `z.object({name: z.string()})`, the return value is a schema object, not the supplied shape: its fields are accessible through `schema.shape`, not `schema.name`. Indexing `name` as a direct child therefore makes definition lookup resolve nonexistent members and exposes incorrect skeletons for every such schema.
- [P2] Account for shadowing when resolving object receivers — src/analyzer/usages/get_definition.rs:813-814 — When a function parameter or local variable shadows a top-level object, `file_identifier` still finds the top-level declaration. For example, `const config = {port: 1}; function f(config: Other) { return config.port; }` now resolves the parameter's `port` to the unrelated top-level property. The receiver must be bound at the reference site before using its indexed members.
- [P2] Require all return paths to preserve the argument — src/analyzer/typescript/mod.rs:1152-1154 — A function with even one `return parameter` is classified as shape preserving, including `function wrap(x) { if (condition) return x; return {}; }`. Consequently the result of `wrap({foo: 1})` is indexed with a `foo` member even on paths where it does not exist, producing false definitions and skeletons.
