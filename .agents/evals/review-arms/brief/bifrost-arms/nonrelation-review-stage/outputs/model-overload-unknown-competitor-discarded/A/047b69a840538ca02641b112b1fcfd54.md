- [P1] Preserve uncertainty from other overload candidates — crates/bifrost-analysis/src/analyzer/usages/call_conversion.rs:837-838. When one overload converts successfully but another cannot be analyzed (for example, its formal type is generic or its declaration cannot be resolved), this selects the first overload as exact even though the other may also apply or be more specific. A conversion error is recorded as `ConversionUnknown`, not proof that the candidate is inapplicable, so this can attach the wrong model member and produce incorrect policy results.
- [P1] Do not apply scalar primitive conversions to array elements — crates/bifrost-analysis/src/analyzer/java/call_conversion.rs:467-468. For an `int[]` argument and a `long[]` formal, this recursively proves primitive widening, although Java does not permit conversion between those array types. The same problem applies to boxing and unboxing, so model overload selection and conversion facts can identify an inapplicable signature as exact.
- [P2] Preserve formal names in shared non-Java layouts — crates/bifrost-analysis/src/analyzer/semantic_model/overlay.rs:2293-2296. When non-Java overloads have the same positional shape but different parameter names, this now marks them compatible, and the non-Java binder emits the first signature's formal names as exact for every overload. A positional call can therefore be associated with the wrong named formal in policy queries; the existing compatible-layout path does not select a particular overload.
