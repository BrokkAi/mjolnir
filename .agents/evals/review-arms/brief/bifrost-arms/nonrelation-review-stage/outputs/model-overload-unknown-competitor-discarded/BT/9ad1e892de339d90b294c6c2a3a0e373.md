- [P1] Keep unresolved overloads from proving a unique selection — crates/bifrost-analysis/src/analyzer/usages/call_conversion.rs:837-838
  When one overload converts successfully but another returns an unknown reason such as `UnresolvedTargetType` or `GenericSubstitution`, this selects the first as exact even though the other may also apply or be more specific. A partially modeled overload family can therefore produce an incorrect model member and policy result; unknown applicability must remain inconclusive rather than count as rejection.
- [P1] Do not apply scalar conversions to array elements — crates/bifrost-analysis/src/analyzer/java/call_conversion.rs:467-468
  For a modeled `long[]` parameter and an `int[]` actual, this recurses into the scalar classifier and proves primitive widening, although Java does not allow `int[]` to convert to `long[]`. The same problem affects boxing and unboxing of array elements, allowing invalid conversion evidence and potentially selecting the wrong overload.
- [P2] Preserve formal names when comparing shared layouts — crates/bifrost-analysis/src/analyzer/semantic_model/overlay.rs:2293-2296
  For non-Java overloads with the same positional layout but different parameter names, a positional call now yields `CompatibleLayout`, and the binder emits the first signature's formal names as exact even though no overload was selected.
