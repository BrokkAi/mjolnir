- [P2] Resolve field types in the declaring file's import context — src/analyzer/usages/get_definition.rs:1094-1095
  When a field's type name is imported differently in the referencing file and the declaring file, the new import-aware lookup resolves the reference file's unrelated type first and never consults the field's actual imports. For example, if `Outer.inner` is declared as `Inner` from module A but the caller imports module B's `Inner`, lookup of `outer.inner.member` searches B's members and can return the wrong definition or no definition.
- [P2] Honor custom unwrap and expect return types — src/analyzer/usages/get_definition.rs:984-993
  When a user-defined type has an `unwrap` or `expect` method that returns a different type, this branch treats the result as the receiver's type and bypasses the indexed method signature. Consequently, field lookup on a local initialized by that method resolves against the wrong struct; these method names are not exclusive to `Option` or `Result`.
- [P2] Distinguish method calls inside macro token trees — src/analyzer/usages/get_definition.rs:658-662
  When a macro contains a call such as `value.member()` and the type has both a field and a method named `member`, the dotted-text path always selects the field even though Rust resolves the call to the method. The ordinary AST path distinguishes calls, but macro token trees reach this fallback and therefore return the wrong definition.
