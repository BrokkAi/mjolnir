- [P2] Resolve field types in the field declaration's scope — src/analyzer/usages/get_definition.rs:1094-1095. When a field's type name is imported differently in the accessing file and the file declaring the field, the new import-aware lookup resolves the accessing file's import first and never checks the declaration's scope. For example, if `Outer.inner` is declared as `a::Inner` via an import but the caller imports `b::Inner`, looking up `outer.inner.value` resolves `value` against `b::Inner` and can return the wrong definition or no definition.
- [P2] Respect user-defined `unwrap` and `expect` methods — src/analyzer/usages/get_definition.rs:984-993. When a user-defined type has an `unwrap` or `expect` method returning a different type, this branch assumes the result has the receiver's type and skips the method's indexed return signature. Consequently, a lookup such as `wrapper.unwrap().field` now searches for `field` on `Wrapper` instead of the actual return type, even though the existing method-return resolution handled this case.
