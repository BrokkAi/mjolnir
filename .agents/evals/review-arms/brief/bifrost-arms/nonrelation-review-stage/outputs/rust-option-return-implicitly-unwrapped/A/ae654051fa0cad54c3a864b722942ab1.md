- [P2] Resolve field types in the field declaration's import context — src/analyzer/usages/get_definition.rs:1117-1123. When a field's declared type is imported in its defining module and the accessing module imports a different type with the same name, the new bare-import lookup resolves the field type using the accessing module first. For `outer.inner.name`, this can return the other type's `name` field (or report it missing) even though the field declaration identifies a different owner; the declaration's source context needs to take precedence when resolving its type.
- [P2] Preserve return types of user-defined unwrap methods — src/analyzer/usages/get_definition.rs:984-993. When a project type defines its own `unwrap` or `expect` method returning another struct, this branch treats the receiver itself as the result and skips the indexed method signature. A subsequent lookup such as `wrapper.unwrap().field` consequently searches for `Wrapper.field` instead of the returned struct's field, regressing cases that previously resolved through the method's return type.
