- [P2] Resolve field types in the declaration's import context — src/analyzer/usages/get_definition.rs:1094-1095
  When a field's type name is imported differently in its declaring file and the file accessing it, the new import-aware lookup resolves the signature using the accessing file first. For example, if `Holder.item` is declared as `a::Item` via `use a::Item`, but the caller imports `b::Item`, looking up `holder.item.name` resolves `name` against `b::Item` and can return the wrong definition. The type in the field signature must be interpreted in the field's source context.
- [P2] Resolve user-defined unwrap and expect methods by their return type — src/analyzer/usages/get_definition.rs:984-993
  When a user-defined type has an `unwrap` or `expect` method returning a different struct, this branch treats the result as the receiver's type and bypasses the existing method return-type lookup. Consequently, `let value = wrapper.unwrap(); value.field` resolves against `wrapper`'s type or reports no definition even when the returned struct and field are indexed.
