- [P1] Index impl blocks inside inline modules — src/analyzer/rust_analyzer.rs:537-561
  When an inline module contains a struct and its `impl`, the module visitor ignores the impl entirely, so its methods and associated constants never appear in definitions, members, or skeletons. The same visitor also skips module-level aliases, constants, statics, and imports, despite indexing those constructs at the file root.
- [P2] Handle visibility on use declarations — src/analyzer/rust_analyzer.rs:73-74
  For a common re-export such as `pub use crate::foo::Bar;`, the raw text starts with `pub use`, so `flatten_rust_use` does not recognize it and the resolver looks up a name containing `pub use`. Consequently re-exports are never resolved and grouped public imports are not flattened.
- [P2] Resolve glob imports to their imported declarations — src/analyzer/rust_analyzer.rs:882-887
  For `use crate::foo::*`, stripping the glob and looking up only `foo` returns the module declaration, if one exists, rather than the declarations imported from it. In the usual separate-file module layout this can even point to the file containing `mod foo;` instead of `foo.rs`, making imported-code-unit and referencing-file results incorrect.
- [P2] Index trait methods with default bodies — src/analyzer/rust_analyzer.rs:481-490
  Trait methods with bodies are `function_item` nodes, whereas only `function_signature_item` is handled here. A trait such as `trait T { fn f(&self) {} }` therefore loses `f` from its members and skeleton even though required methods are indexed.
- [P2] Detect test attributes structurally — src/analyzer/rust_analyzer.rs:53
  This substring check marks ordinary files containing these strings in comments or string literals as test files, and misses valid attributes with whitespace such as `#[test ]` or `#[cfg( test )]`. This makes test-module and test-file classification depend on formatting and unrelated source text.
