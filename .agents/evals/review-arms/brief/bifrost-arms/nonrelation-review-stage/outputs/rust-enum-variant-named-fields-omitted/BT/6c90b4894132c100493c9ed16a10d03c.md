- [P1] Avoid indexing non-Rust files in Rust updates — src/analyzer/rust_analyzer.rs:277-278
  When a `MultiAnalyzer` updates a Java, JavaScript, or TypeScript file, it passes that file to every delegate, and the shared update parses every supplied existing file without checking its extension. The new Rust delegate therefore indexes other languages as Rust, adding spurious definitions to aggregated queries and making its analyzed-file set inconsistent with the initial build.
- [P2] Visit implementations and imports inside inline modules — src/analyzer/rust_analyzer.rs:537-561
  For ordinary inline modules such as `mod m { struct S; impl S { fn f() {} } use crate::other::T; }`, the visitor ignores the `impl` and `use` nodes entirely. Consequently `m.S.f` is absent from definition and member queries, and imports and references within the module are never reported; constants and type aliases in the same scope are also skipped.
- [P2] Parse public use declarations before resolving them — src/analyzer/rust_analyzer.rs:774-777
  For a valid re-export such as `pub use crate::foo::Bar;`, the node text starts with `pub use` and falls into this branch. Subsequent import parsing only strips `use `, so it looks up `pub use crate.foo.Bar` and fails to report the imported definition or the referencing file; grouped public imports are not flattened either.
- [P2] Resolve wildcard imports to module contents — src/analyzer/rust_analyzer.rs:882-887
  For `use crate::foo::*`, this removes the wildcard and performs an exact definition lookup for `foo`. A typical `src/foo.rs` has definitions such as `foo.Bar` but no `foo` definition in that file, so imported units and referencing-file queries miss every item brought into scope by the wildcard.
- [P2] Index provided trait methods — src/analyzer/rust_analyzer.rs:477-491
  Trait methods with default bodies are `function_item` nodes, while this visitor only handles `function_signature_item`. For `trait T { fn f(&self) {} }`, `T.f` is therefore missing from definitions, member queries, and the trait skeleton, even though required trait methods are indexed.
- [P2] Distinguish test attributes from source text — src/analyzer/rust_analyzer.rs:53-53
  A comment or string containing `#[test]` or `#[cfg(test)]` makes this return true even when the file has no test attribute. As a result `contains_tests` and aggregate test-file queries report ordinary source files as tests; checking parsed attribute nodes would avoid these false positives.
