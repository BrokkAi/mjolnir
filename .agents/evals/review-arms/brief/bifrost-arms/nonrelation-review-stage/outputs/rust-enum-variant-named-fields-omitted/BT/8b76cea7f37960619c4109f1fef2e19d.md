- [P1] Traverse implementations inside inline modules — src/analyzer/rust_analyzer.rs:537-561 — When an inline module contains `impl Foo { ... }`, its implementation is skipped entirely, so methods and associated constants are absent from definition and member queries. The same match also drops module-level type aliases, constants, and statics, although their top-level equivalents are indexed.
- [P2] Parse imports inside inline modules — src/analyzer/rust_analyzer.rs:67-72 — Only root-level `use` declarations are collected, so imports in an inline module are missing from import metadata and dependency queries. This is common in test modules and other nested modules, and resolving relative `self`/`super` imports also requires retaining the enclosing module path.
- [P2] Handle visibility on use declarations — src/analyzer/rust_analyzer.rs:776-779 — A declaration such as `pub use crate::foo::Bar;` does not start with `use `, so it is returned unflattened and later resolved as `pub use crate.foo.Bar`. Consequently re-exports never resolve to their definitions, and grouped public imports are not expanded.
- [P2] Resolve glob imports to the imported members — src/analyzer/rust_analyzer.rs:882-886 — For `use crate::foo::*`, stripping the glob and looking up only `foo` does not return the declarations in that module; for a file-backed module there may not even be a `foo` definition. As a result imported-code-unit and referencing-file queries miss actual dependencies introduced by wildcard imports.
- [P2] Detect test attributes from syntax rather than source substrings — src/analyzer/rust_analyzer.rs:53 — A comment or string containing `#[test]` marks an ordinary file as a test file, while valid attributes with whitespace such as `#[cfg( test )]` are missed. This propagates incorrect results through `contains_tests` and test-file queries.
