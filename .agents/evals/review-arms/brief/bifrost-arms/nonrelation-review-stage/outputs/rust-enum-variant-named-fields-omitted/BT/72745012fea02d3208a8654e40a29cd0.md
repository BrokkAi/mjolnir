- [P1] Restrict Rust updates to Rust files — src/analyzer/rust_analyzer.rs:278-280. When a mixed-language `MultiAnalyzer` updates a Java, JavaScript, or TypeScript file, it passes that file to every delegate and the shared update parser accepts every existing path. The Rust delegate therefore parses and indexes the non-Rust file as Rust, contaminating global definition and reference queries after an incremental update.
- [P2] Index impls and other declarations inside modules — src/analyzer/rust_analyzer.rs:537-561. For an inline module containing an `impl`, `type`, `const`, or `static` item, this dispatch ignores the item entirely. For example, `mod m { struct S; impl S { fn f() {} } }` indexes `m.S` but never indexes `m.S.f`, so member and definition queries lose ordinary module contents.
- [P2] Collect imports inside inline modules — src/analyzer/rust_analyzer.rs:532-537. A `use` nested in an inline module is never visited, so its import metadata, imported units, and reverse references are all absent; this affects common files that organize their implementation or tests in inline modules.
- [P2] Parse public use declarations — src/analyzer/rust_analyzer.rs:778-780. For `pub use crate::module::Type;` or `pub(crate) use ...`, the raw declaration does not start with `use `, so it is returned unchanged and the resolver treats `pub use crate` as a path segment. Consequently re-exports cannot resolve and grouped public imports are not flattened.
- [P2] Resolve wildcard imports to the module's declarations — src/analyzer/rust_analyzer.rs:871-874. For `use crate::module::*`, stripping the wildcard and looking up only the module name cannot return the items imported from a separate `module.rs` file, because its declarations are indexed under names such as `module.Type`. Imported-unit and referencing-file queries therefore miss glob dependencies.
- [P2] Detect test attributes from syntax instead of text — src/analyzer/rust_analyzer.rs:52-53. A comment or string containing `#[test]` or `#[cfg(test)]` marks the entire file as containing tests, while valid attributes with whitespace such as `#[test ]` are missed. This makes test-file queries incorrect for both ordinary documentation and valid Rust formatting.
- [P2] Include provided trait methods in class members — src/analyzer/rust_analyzer.rs:481-490. Trait methods with default bodies are `function_item` nodes, but this branch only accepts `function_signature_item`, so `trait T { fn f(&self) {} }` has no indexed `T.f` even though required methods are indexed.
