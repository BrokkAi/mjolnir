- [P1] Index implementations inside inline modules — src/analyzer/rust_analyzer.rs:537-562 — When an inline module contains `struct S; impl S { fn f() {} }`, the module visitor ignores the `impl_item`, so `module.S.f` is never indexed. The same match also drops module-level constants, statics, aliases and imports, making ordinary inline modules substantially incomplete.
- [P2] Resolve glob imports to the imported module's contents — src/analyzer/rust_analyzer.rs:203-207 — For `use crate::foo::*`, resolution strips the glob and looks up only `foo`, rather than the declarations in that module. With `mod foo;` in `lib.rs` and definitions in `foo.rs`, this returns the module declaration in `lib.rs` and misses the imported definitions in `foo.rs`, so both imported units and reverse file references are wrong.
- [P2] Handle visibility on use declarations — src/analyzer/rust_analyzer.rs:72-75 — A common re-export such as `pub use crate::foo::Thing;` is passed to `flatten_rust_use` with its visibility intact, but that function only recognizes strings beginning with `use `. Consequently its import path is parsed as `pub use crate...` and cannot resolve, and grouped public imports are not flattened at all.
- [P2] Index trait methods with default bodies — src/analyzer/rust_analyzer.rs:481-491 — A trait method with a default implementation is a `function_item`, but this branch only handles `function_signature_item`. Such methods disappear from definition lookup and trait skeletons even though required methods in the same trait are indexed.
- [P2] Determine test attributes from syntax rather than raw substrings — src/analyzer/rust_analyzer.rs:53-53 — A comment or string containing `#[test]` marks a production file as a test file, while valid attributes with whitespace such as `#[test ]` are missed. This propagates to the test-detection and test-file selection APIs.
