- [P1] Index impls and other declarations inside inline modules — src/analyzer/rust_analyzer.rs:537-561. When a Rust file contains an inline module, its `impl` blocks, type aliases, constants, statics, and `use` declarations are skipped entirely. For example, `mod m { struct S; impl S { fn f() {} } }` indexes `m.S` but never indexes `m.S.f`, so member lookup and import analysis miss ordinary module contents.
- [P2] Handle visibility on use declarations before flattening — src/analyzer/rust_analyzer.rs:781-783. For a re-export such as `pub use crate::foo::Bar;`, the text does not start with `use `, so it is passed through unchanged; the import parser and resolver then treat `pub use crate` as part of the path. Consequently re-exports cannot resolve to their definitions and grouped public imports are not flattened.
- [P2] Resolve wildcard imports to the imported members — src/analyzer/rust_analyzer.rs:895-896. For `use crate::foo::*`, stripping `::*` and looking up only `foo` returns the module declaration, not the declarations imported from that module. This also causes imports from a file-backed module with no indexed module declaration to resolve to nothing, making imported-unit and referencing-file results incorrect.
- [P2] Retain the file stem for non-src module files — src/analyzer/rust_analyzer.rs:424-432. When a crate root is outside a directory literally named `src`, such as `lib.rs` with sibling `foo.rs`, declarations in `foo.rs` are indexed at the root instead of under `foo`. Thus `use crate::foo::Thing` cannot resolve and same-named declarations in sibling modules collide.
- [P2] Include default trait methods in the index — src/analyzer/rust_analyzer.rs:477-491. A trait method with a default body is parsed as `function_item`, but this branch handles only `function_signature_item`; therefore `trait T { fn f(&self) {} }` never exposes `T.f` in definitions or members.
