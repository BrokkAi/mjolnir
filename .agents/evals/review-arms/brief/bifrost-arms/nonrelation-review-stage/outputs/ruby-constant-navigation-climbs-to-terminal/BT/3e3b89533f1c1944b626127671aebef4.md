- [P1] Honor prepended modules before direct methods — src/analyzer/usages/ruby_graph.rs:380-383. When a class prepends a module that defines the same method as the class, Ruby invokes the module method first, but this early return always selects the class method. This also gives rename and usage filtering the wrong definition for those calls.
- [P1] Interleave ancestor methods with their mixins — src/analyzer/usages/ruby_graph.rs:391-403. If a subclass inherits a method defined directly on its parent and a more distant ancestor includes a module defining the same method, this searches all ancestors' mixins before any ancestor's direct methods and returns the module method instead of the parent's overriding method.
- [P2] Preserve inclusion order when resolving competing mixins — src/analyzer/usages/ruby_graph.rs:391-398. When a class includes two modules that both define the called method, Ruby selects the most recently included module, but the hash-set iteration collects both and reports an ambiguous result. The relation index must retain the relevant ordering to select the actual definition.
- [P2] Resolve the selected component of a qualified constant — src/analyzer/usages/get_definition/ruby.rs:107-109. Selecting `A` in `A::B` climbs to the whole scope resolution and returns the definition of `A::B` instead of `A`; this also makes source-based rename select the wrong symbol or reject the selection.
- [P2] Process assignments inside preceding control-flow nodes — src/analyzer/usages/get_definition/ruby.rs:283-287. When a local is assigned inside a preceding `if` or other enclosing statement, that entire statement is skipped, so a subsequent `value.method` cannot infer its receiver even when the assignment constructs an indexed class.
