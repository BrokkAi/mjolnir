If a class prepends a module that defines the same method, Ruby dispatches to the prepended module before the class, but this early return always selects the class method. The index also combines prepend and include relations, so the resolver cannot currently distinguish their precedence.

If a superclass defines a method and also includes a module defining it, a call on a subclass resolves to the superclass method in Ruby, but this loop returns the module method before examining any superclass definitions. The same error occurs when a nearer ancestor defines a method and a more distant ancestor includes a module with that name.
- [P2] Preserve the order of multiple included modules — src/analyzer/usages/ruby_graph.rs:391-398. When a class includes two modules that define the same method, Ruby uses the most recently included module, but the hash-set iteration collects both definitions and returns an ambiguous result. Source order is required to select the method Ruby actually invokes.
- [P2] Traverse earlier control-flow statements for local inference — src/analyzer/usages/get_definition/ruby.rs:283-287. When an earlier `if` or other compound statement assigns a constructed receiver, such as `if condition; user = User.new; end` followed by `user.audit`, the whole statement is skipped without visiting its assignment. The receiver therefore has no inferred type and the supported method lookup fails.
