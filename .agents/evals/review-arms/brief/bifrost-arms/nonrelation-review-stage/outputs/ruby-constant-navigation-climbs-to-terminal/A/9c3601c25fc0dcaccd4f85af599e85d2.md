- [P2] Interleave ancestor methods with their mixins — src/analyzer/usages/ruby_graph.rs:391-398 — When a superclass defines a method and one of its included modules defines the same method, a call on a subclass resolves to the superclass method in Ruby. This loop checks all ancestors' mixins before checking any ancestor's own methods, so it instead returns the module method.
- [P2] Preserve ordering between included modules — src/analyzer/usages/ruby_graph.rs:391-395 — If a class includes two modules that both define the called method, Ruby selects the most recently included module. Iterating the unordered set and returning all matching methods instead yields an ambiguous result rather than the actual definition; the same issue applies to multiple `extend` calls.
- [P2] Resolve each component of a qualified constant independently — src/analyzer/usages/get_definition/ruby.rs:107-110 — When the cursor is on `A` in `A::B`, this climbs to the entire scope resolution and returns the definition of `A::B` instead of `A`. This also prevents navigating to a valid prefix when the final constant cannot be resolved.
- [P2] Treat class-body calls as class receiver calls — src/analyzer/usages/get_definition/ruby.rs:298-301 — For a bare call in a class or module body, such as `class User; def self.configure; end; configure; end`, no method mode is pushed, so the shared enclosing-receiver helper defaults to instance mode. The lookup consequently misses the class method or returns an unrelated instance method of the same name.
