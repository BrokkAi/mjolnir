- [P1] Evaluate the right operand before the assignment place — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:2135-2136. Rust evaluates the right operand of a simple assignment before evaluating its assignee, but this schedules the base and index first. For `items[next_index()] = produce()`, the resulting control and value-flow graph reverses the calls, and can incorrectly report reachability or effects when either call mutates state or exits abruptly. Field stores have the same ordering problem.
- [P1] Do not infer absence of Drop from a single file — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:4038-4042. A `Drop` implementation for a type declared here may legally appear in another module file in the same crate. The prescan then classifies that struct as plain and suppresses scope-exit and assignment cleanup gaps, even though its destructor can execute arbitrary user code. The proof needs to account for implementations outside the prepared file.
- [P2] Canonicalize equivalent constant indices — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:1045-1054. Equivalent Rust integer literals such as `0` and `0usize` or `0x0` are interned as distinct exact selectors. A store through one spelling and a load through another therefore name different access paths, losing a real heap flow without an index-memory gap.
- [P2] Resolve field owner identity before accepting file-local declarations — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:4070-4088. A bare type name can refer to an imported struct while an unrelated struct with the same name is declared in another module of this file. The table keys only on the spelling, so a parameter of the imported type can be assigned the unrelated declaration's field identity and primitive type, suppressing field and cleanup gaps and producing incorrect memory flow.
