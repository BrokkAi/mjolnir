- [P1] Evaluate the assignment value before the target place — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:2135-2136
  For an assignment such as `array[index()] = value()`, Rust evaluates the right-hand side before the target place, but these insertions schedule `index()` before `value()`. Side effects, calls, and early exits are therefore ordered incorrectly in the control-flow and value-flow graphs; field targets have the same problem.

- [P1] Do not infer absence of Drop from a single file — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:4154-4156
  A struct may have its `impl Drop` in another module of the same crate. In that common layout this file scan still classifies the struct as plain, so a local initialized with it loses the cleanup, call, and exceptional-control gaps even though its destructor executes and can affect later analysis.

- [P2] Canonicalize equivalent constant indices — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:1045-1054
  Different Rust literal spellings can denote the same index, such as `0` and `0usize` or `1` and `0x1`. Interning by source text gives them distinct exact selectors without an index-memory gap, so a store through one spelling and a load through the other are treated as different locations and value flow can be missed.
