- [P1] Resolve the callee before inferring its return type — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:1225-1230
  When a local closure, function parameter, or imported function shadows a same-named function declared elsewhere in the file, this lookup attributes the unrelated declaration's primitive return type to the call. For example, a closure returning a guard can be classified as non-dropping because another module contains `fn make() -> i32`; the guard's cleanup and destructor-call gaps are then omitted, making downstream flow results incorrectly complete. The repository's guidance requires unresolved names to remain a structured best-effort result rather than hide a resolvable failure ([AGENTS.md:477-481](AGENTS.md#L477-L481)).

- [P1] Do not identify field declarations by unqualified type name — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:913-917
  If a module imports an external `Holder` while another module in the same file declares a different `Holder`, a parameter of the imported type is matched to the unrelated local struct. Its field is then assigned the wrong declaration identity, and the field-memory and implicit-call gaps are suppressed even though the external type may require user `Deref` or have a different field type. This can silently miss heap flows and destructor effects; unresolved type identity must remain uncertain ([AGENTS.md:477-481](AGENTS.md#L477-L481)).

- [P2] Canonicalize constant indices before assigning exact identities — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:1045-1054
  When the same array element is accessed using different equivalent literals, such as `values[0] = source;` followed by `values[0usize]`, these occurrences receive different exact index values. Both accesses are treated as resolved, so the store and load fail to meet without an index-memory gap, losing the value flow for valid Rust programs.
