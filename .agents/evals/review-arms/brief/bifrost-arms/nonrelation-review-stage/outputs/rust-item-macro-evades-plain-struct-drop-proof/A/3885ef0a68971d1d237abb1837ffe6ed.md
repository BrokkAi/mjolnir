- [P1] Preserve cleanup uncertainty for overloaded operators — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:1156-1161. When an operator is implemented by a non-dropping operand type, its `Output` can still implement `Drop`; for example, `Plain + Plain` can return a guard. Classifying the result from its operands suppresses the guard's cleanup and call gaps, so downstream analysis can incorrectly treat scope exit as having no destructor effects.
- [P1] Resolve struct identity before using same-name field declarations — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:909-916. A parameter can name an imported `Holder` while an unrelated module in the same file declares another `Holder` with the same field name. This lookup selects the unrelated declaration, suppressing the field identity and implicit dereference gaps and potentially claiming the field is primitive even when the actual field has a destructor. Uniqueness of the spelling within this file does not establish which type the parameter names.
- [P2] Do not infer absence of Drop from a single file — crates/bifrost-analysis/src/analyzer/rust/semantic.rs:4110-4124. Rust permits an `impl Drop` for a type in another file of the same crate, so a named struct with primitive fields can be classified as plain here even though its destructor runs user code. Struct literals of that type then suppress the cleanup, resource and call gaps at scope exit.
