- [P1] Include all requested overloads in the graph query — src/usages/csharp_graph.rs:43-43. When a usage query supplies multiple overloads, the graph builds its specification solely from the first one and returns success, so calls with the arities of the remaining overloads are silently omitted and regex fallback never runs.
- [P1] Retain candidate files that use aliases or static imports — src/analyzer/csharp_analyzer.rs:284-305. A consumer in another directory using `using Alias = Domain.Target;` or `using static Domain.Target;` is absent from the reverse namespace index and generally has no matching qualified type identifier. The candidate provider therefore excludes it before the graph can detect the unsupported form and request fallback, causing valid references to disappear from normal usage queries.
- [P2] Account for optional and variadic parameters when matching calls — src/usages/csharp_graph.rs:324-329. A constructor with optional parameters or a `params` parameter can legally be invoked with an argument count different from its declared parameter count, but this check drops those calls and returns a successful incomplete result. The equivalent method check has the same problem.
- [P2] Recognize type references used as static member receivers — src/usages/csharp_graph.rs:620-624. For `Target.Configure()` or `Target.Count`, the `Target` identifier is inside a member access rather than a type field, so this predicate rejects it and a search for the type omits these valid references while reporting success.
- [P2] Respect lexical scope when inferring receiver bindings — src/usages/csharp_graph.rs:470-475. The traversal seeds declarations from every earlier block, including blocks that have already ended. For example, after `{ Target x = new Target(); }`, a separate block declaring `Other x` can be misidentified depending on the intervening declarations, or an out-of-scope local can be used to prove a later receiver; this produces incorrect graph hits instead of fallback.
- [P2] Resolve namespaces at the reference location — src/analyzer/csharp_analyzer.rs:155-159. A C# file can contain declarations in multiple namespace blocks, but choosing the first declaration's namespace for the entire file causes references in the other blocks to resolve against the wrong namespace and also prevents same-namespace candidate discovery for those blocks.
