- [P1] Include qualified static references in candidate selection — src/analyzer/csharp_analyzer.rs:288-305. When a file in another directory uses `Domain.Target.Run()` without a `using Domain` directive, the receiver is an expression rather than a type position, so `type_identifiers_of` does not contain `Domain.Target`. The file is omitted from the candidate set and the graph returns a successful result without this usage, even though its member scanner can resolve the qualified receiver.
- [P2] Do not discard calls with omitted or expanded arguments — src/usages/csharp_graph.rs:324-329. C# constructors can have optional parameters or a `params` array, so a valid `new Target()` can call `Target(int value = 0)` and `new Target(1, 2)` can call `Target(params int[] values)`. Requiring the argument count to equal the declared parameter count silently drops these usages and reports a successful incomplete result; the same check for methods at lines 344–351 has the same defect.
- [P2] Consider all overloads when matching calls — src/usages/csharp_graph.rs:43-43. UsageFinder passes a slice of overloads, but the strategy builds its specification solely from the first one and filters calls by that overload's arity. A query containing `Run()` and `Run(int)` therefore omits calls to whichever overload is not first, while returning success and preventing fallback.
