- [P1] Include qualified static member consumers in candidate files — src/analyzer/csharp_analyzer.rs:288-305. A file in another namespace that calls `Domain.Target.Run()` without a `using Domain` directive has no imported namespace or type-position identifier for `Domain.Target`: the receiver is a member-access expression. Consequently it is omitted from the candidate set, so the graph never sees this valid reference and returns an incomplete result. The same omission affects fully qualified static field and property accesses.
- [P1] Search every supplied overload — src/usages/csharp_graph.rs:43-43. When a name resolves to multiple C# overloads, only the first overload supplies the target and arity, so calls to the other overloads are silently discarded. LSP references explicitly passes all matching overloads, making its results incomplete whenever their parameter counts differ.
- [P2] Preserve calls with optional or params arguments — src/usages/csharp_graph.rs:344-351. C# permits calls with fewer arguments than the declared parameter count for optional parameters and variable numbers of arguments for `params` parameters. The exact arity check discards these valid calls without triggering fallback; the same issue affects constructors at lines 324–329.
- [P2] Respect the caller's filtered candidate set — src/usages/csharp_graph.rs:66-71. When a file filter excludes the target's source, or the candidate set is truncated by the file limit, this unconditionally adds that source back to the scan. References in the excluded file can therefore appear in results and can also cause a callsite-limit result even though the caller did not permit that file to be searched.
