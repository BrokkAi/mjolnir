- [P1] Preserve bindings in while-let bodies — crates/bifrost-rust/src/structural.rs:427. For `while let Some(x) = value { ... }`, the Rust grammar names the loop body `body`, not `consequence`, so this lookup returns `None` and drops every pattern binding in the loop. The file environment is marked incomplete and references to the loop variable cannot resolve, affecting all consumers of that environment.
- [P2] Keep if-let bindings active in later let-chain conditions — crates/bifrost-rust/src/structural.rs:427-431. In a Rust let chain such as `if let Some(x) = opt && x > 0 { ... }`, `x` is also in scope in the subsequent condition, but this interval starts at the consequence body. References in the rest of the condition therefore resolve to an outer `x` or become unresolved, producing incorrect lexical identities for valid Rust code.
- [P2] Preserve return-branch detection for computed Rust conditions — crates/bifrost-analysis/src/analyzer/structural/branch_relations.rs:330-333. A previously supported example such as `if x > 0 { return true; } else { return false; }` now produces no relation because `rust_boolean_expression` rejects binary expressions. Rust already requires an `if` condition to be Boolean, and the existing diagnostic only reports the complementary returns, so this gate suppresses valid findings for comparisons, calls, and other common conditions.
- [P2] Do not classify discarded literals as branch results — crates/bifrost-analysis/src/analyzer/branch_boolean.rs:84-88. For valid statement-position code such as `if c { true; } else { false; }`, the existing wrapper loop unwraps each `expression_statement` and this new literal case treats the discarded values as branch results. The policy consequently reports complementary Boolean returns even though both arms evaluate to `()` and the function returns no Boolean.
