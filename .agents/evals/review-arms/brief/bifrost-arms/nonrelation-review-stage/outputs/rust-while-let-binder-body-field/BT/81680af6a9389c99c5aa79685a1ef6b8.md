- [P2] Preserve while-let binding activation — crates/bifrost-rust/src/structural.rs:427
  For `while let Some(v) = value { ... }`, the owner is a `while_expression`, whose loop block is in the `body` field rather than `consequence`. This returns `None`, so binder collection drops `v` and marks the file's lexical environment incomplete; analyses using the environment lose the previously available binding throughout the loop.
- [P2] Include later let-chain conditions in the binding interval — crates/bifrost-rust/src/structural.rs:431
  In a Rust let chain such as `if let Some(v) = opt && v > 0 { ... }`, `v` is also in scope in the subsequent condition, before the consequence block begins. Restricting activation to the block makes that reference resolve to an outer binding or remain unresolved, so lexical consumers can report incorrect identities or incomplete results for valid code.
