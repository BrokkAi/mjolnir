- [P1] Avoid scanning all blobs after every persistence batch — src/analyzer/store/mod.rs:4751-4756. When a workspace has many current-generation blobs and no stale ones, this inequality against a joined epoch requires scanning the blob registry to find no candidates. Reclamation runs after every persistence batch, so building a large workspace repeatedly scans its growing registry while holding an immediate write transaction, producing quadratic work and blocking other writers even during normal operation with no epoch cutover.
- [P2] Do not cache empty Scala indexes after a transient store error — src/analyzer/tree_sitter_analyzer.rs:4028-4030. If index construction encounters a transient SQLite error, this returns an empty index as a successful result; Scala's `project_types()` then permanently caches a `ProjectTypes` containing that handle, so subsequent usage resolution keeps missing project definitions even after the database recovers. The same issue applies to the usage-facts fallback. Propagate the failure through the outer cache or construct a complete index before caching it.
