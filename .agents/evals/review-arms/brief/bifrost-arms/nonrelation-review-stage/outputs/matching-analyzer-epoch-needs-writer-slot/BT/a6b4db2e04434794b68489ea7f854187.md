- [P1] Preserve analyzed files when the captured generation becomes stale — src/analyzer/tree_sitter_analyzer.rs:2742-2743. If another analyzer publishes a new epoch while this analyzer is still in use, the generation-qualified lookup returns an error and `unwrap_or_default()` treats every previously persisted file as absent. Consequently `analyzed_files()` and Scala's `all_files()` silently lose the workspace, even though its live paths and source files still exist; subsequent incremental updates only recover files that happen to be changed. The stale-generation case needs a way to retain or reconstruct the analyzer's file set rather than interpreting the failed lookup as an empty result.
- [P1] Do not cache empty Scala project indexes after a cutover — src/analyzer/tree_sitter_analyzer.rs:4029-4030. When an epoch changes before the first lazy index build, the generation check fails and this returns the permanently empty fallback. Scala's `project_types()` then stores that handle in its own `OnceLock`, so usage and type resolution continue to miss workspace definitions for the lifetime of that analyzer even though the inner index lock remains uninitialized. The same issue applies to the callable-facts fallback. This silently masks a structured failure, contrary to [AGENTS.md:100](/workspace/6841c5684dbb7c35644728b9b20dd170/bifrost-dev/AGENTS.md:100).
