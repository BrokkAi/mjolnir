## Value flow
- JS property names are appended to the owning variable's short name with an empty package (`src/analyzer/javascript/mod.rs:944`); that owner name includes the source filename for root fields (`src/analyzer/javascript/mod.rs:881`), and `CodeUnit::fq_name` returns the short name unchanged for an empty package (`src/analyzer/model.rs:367`).
- Property nodes passed to `add_code_unit` by the JS and TS visitors (`src/analyzer/javascript/mod.rs:950`, `src/analyzer/typescript/mod.rs:1214`) become declaration entries, node ranges, and parent-child entries (`src/analyzer/tree_sitter_analyzer.rs:212`, `src/analyzer/tree_sitter_analyzer.rs:218`); analyzer indexing inserts declarations into the definition lookup index (`src/analyzer/tree_sitter_analyzer.rs:713`).
- The existing `config` fixture uses an object followed by `satisfies Config` (`tests/fixtures/testcode-ts/ModernFeatures.ts:11`); the new TS initializer extractor descends through `satisfies_expression`, `as_expression`, and `type_assertion` to obtain the object whose properties are indexed (`src/analyzer/typescript/mod.rs:964`).
- Imported receiver names and kinds (`src/analyzer/usages/get_definition.rs:795`) originate in the import binder: named imports store the imported name under their local alias (`src/analyzer/usages/js_ts_graph/extractor.rs:1136`), default imports store `Default` (`src/analyzer/usages/js_ts_graph/extractor.rs:1104`), and destructured require bindings store `Named` (`src/analyzer/usages/js_ts_graph/extractor.rs:1058`).
- The module helper passes the importing file, module text, language, and alias resolver to module-specifier resolution (`src/analyzer/usages/get_definition.rs:922`); that resolver uses config alias candidate bases for non-relative specifiers and the importing file's parent for relative specifiers (`src/analyzer/js_ts/imports.rs:361`, `src/analyzer/js_ts/imports.rs:378`).
- Member lookup appends the member text to each receiver FQN (`src/analyzer/usages/get_definition.rs:995`) and queries the exact FQN table populated by `DefinitionLookupIndex::insert` (`src/analyzer/definition_lookup_index.rs:25`, `src/analyzer/definition_lookup_index.rs:46`); its value/type filters prefer matching-space candidates and retain the original set when that preferred set is empty (`src/analyzer/usages/get_definition.rs:1048`, `src/analyzer/usages/get_definition.rs:1064`).
- Nonempty member candidates enter `candidates_outcome` (`src/analyzer/usages/get_definition.rs:825`), which sorts, deduplicates, and compares FQN/kind keys to select resolved or ambiguous status (`src/analyzer/usages/get_definition.rs:6778`); public definition candidates obtain the property's path and source lines from its primary range (`src/searchtools.rs:1050`).
