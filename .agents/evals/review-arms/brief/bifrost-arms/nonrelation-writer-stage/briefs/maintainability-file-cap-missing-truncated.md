## Value flow
- `Range::span_lines` computes an inclusive line span (`src/analyzer/model.rs:589`); tree-sitter's range producer assigns both line fields from node rows plus one (`src/analyzer/tree_sitter_analyzer.rs:1359`). The report adds another one to each stored endpoint when displaying locations (`src/code_quality.rs:1180`).
- The traversal's `visited` and metrics maps use `CodeUnit` keys (`src/code_quality.rs:706`); their identity includes source, kind, package, short name, signature, and synthetic status, as defined by `PartialEq` and `Hash` (`src/analyzer/model.rs:439`, `src/analyzer/model.rs:452`).
- Java creates implicit constructors as synthetic function units and adds them as class children (`src/analyzer/java_analyzer.rs:1011`). Scoring assigns synthetic units zero own span and zero initial function count, and excludes them from direct-child counts (`src/code_quality.rs:773`, `src/code_quality.rs:795`).
- Per-function complexity comes from `get_source(cu, false)` and counts keywords/operators over the returned text (`src/code_quality.rs:82`). The new scorer stores that value as a maximum and rolls child maxima into parent signals (`src/code_quality.rs:781`, `src/code_quality.rs:807`).
- Finding ordering uses `rel_path_string` before lowercasing paths (`src/code_quality.rs:935`); that existing helper converts relative paths to lossy strings and replaces backslashes with slashes (`src/path_utils.rs:8`). The same helper supplies rendered finding paths (`src/code_quality.rs:1185`).
- `widest_non_empty_range_of` obtains ranges through `IAnalyzer::ranges_of`, which copies the analyzer's range slice (`src/code_quality.rs:958`, `src/analyzer/i_analyzer.rs:113`); the helper selects the largest line span or produces an all-zero range.
- The file-module predicate asks `parent_of` whether a unit has a parent (`src/code_quality.rs:984`); the trait implementation derives a parent name using the last `.`, `$`, `::`, or `->` separator and resolves it through `definitions` (`src/analyzer/i_analyzer.rs:335`).
- Java package modules originate in `module_code_unit` and enter top-level declarations during parsing (`src/analyzer/java_analyzer.rs:99`, `src/analyzer/java_analyzer.rs:1626`); the new file-module predicate excludes Java by source extension (`src/code_quality.rs:996`).
- The predicate checks extensions against `analyzer.languages()` (`src/code_quality.rs:999`), using the extension lists defined by `Language::extensions`, including PHP, Scala, and C# (`src/analyzer/model.rs:28`).
- Report parameters pass through generic serde decoding (`src/searchtools_service.rs:352`); the new parameter type defaults omitted numeric fields to zero (`src/code_quality.rs:1013`), and handler normalization substitutes positive default caps and thresholds (`src/code_quality.rs:1060`).
- Input paths pass through `workspace_rel_path` (`src/code_quality.rs:1123`), whose existing implementation normalizes backslashes, strips leading slashes, and rejects drive-letter prefixes (`src/path_utils.rs:15`); `FilesystemProject::file_by_rel_path` then constructs a `ProjectFile` and checks existence (`src/analyzer/project.rs:156`).
- The new `{report, truncated}` result (`src/code_quality.rs:1206`) becomes a JSON object through `decode_and_run` (`src/searchtools_service.rs:355`). MCP places that object in `structuredContent` and pretty-prints it into `content[0].text` (`src/mcp_server.rs:895`); Python's generic service route serializes the object directly to JSON (`src/searchtools_service.rs:101`).
