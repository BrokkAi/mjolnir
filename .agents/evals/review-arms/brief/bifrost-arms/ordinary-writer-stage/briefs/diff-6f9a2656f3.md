## Affected callers
- Python has a separate `build_reverse_import_index` that resolves bindings, populates its forward cache, and groups importers by target source (`src/analyzer/python_analyzer.rs:224`); it does not call the new shared builder (`src/analyzer/capabilities.rs:64`).
- `MultiAnalyzer::referencing_files_of` calls every delegate's import provider and unions their results, without selecting by the queried file's extension (`src/analyzer/multi_analyzer.rs:171`); these calls reach the indexed implementations in Go (`src/analyzer/go_analyzer.rs:230`), JavaScript (`src/analyzer/javascript_analyzer.rs:226`), Rust (`src/analyzer/rust_analyzer.rs:224`), and TypeScript (`src/analyzer/typescript_analyzer.rs:240`).
- `referencing_files_for` expects an owned `BTreeSet<ProjectFile>` and stores a clone in its per-graph cache (`src/relevance.rs:437`); JavaScript's indexed lookup supplies that set (`src/analyzer/javascript_analyzer.rs:231`). Graph expansion records each returned importer in both adjacency maps and queues newly encountered files (`src/relevance.rs:354`).
- The capability re-export retains `referencing_files_via_imports` alongside the new builder (`src/analyzer/mod.rs:26`); Java still calls that helper before adding references inferred from identifiers within the same package (`src/analyzer/java_analyzer.rs:270`).

## Paths
- The CLI passes the workspace analyzer to `most_relevant_files` (`src/bin/most_relevant_files.rs:81`), which calls the relevance scorer (`src/searchtools.rs:477`). Its import phase builds a graph (`src/relevance.rs:159`) and requests reverse neighbors (`src/relevance.rs:343`), reaching the shared index builder through language providers (`src/analyzer/capabilities.rs:64`). Git results can fill the requested limit before the import phase (`src/relevance.rs:89`).
- `MultiAnalyzer::update` dispatches to delegate updates (`src/analyzer/multi_analyzer.rs:256`), including Go (`src/analyzer/multi_analyzer.rs:105`). Go creates an empty reverse-index lock alongside replacement forward and reverse caches (`src/analyzer/go_analyzer.rs:318`), even when the inner tree-sitter update returns its clone for an empty change set (`src/analyzer/tree_sitter_analyzer.rs:648`).
- JavaScript's `update` and `update_all` allocate new `JsMemoCaches` (`src/analyzer/javascript_analyzer.rs:295`, `src/analyzer/javascript_analyzer.rs:303`); their existing constructor calls now also initialize an empty reverse-index lock (`src/analyzer/javascript_analyzer.rs:129`).
- The delegate's Rust `update_all` route (`src/analyzer/multi_analyzer.rs:125`) rebuilds the inner analyzer (`src/analyzer/rust_analyzer.rs:291`) and creates an empty reverse-index lock (`src/analyzer/rust_analyzer.rs:295`); the inner rebuild enumerates project state anew (`src/analyzer/tree_sitter_analyzer.rs:682`).
- TypeScript checks its per-target reverse cache before initializing the index (`src/analyzer/typescript_analyzer.rs:236`, `src/analyzer/typescript_analyzer.rs:240`). Its `update` and `update_all` routes replace that index (`src/analyzer/typescript_analyzer.rs:317`, `src/analyzer/typescript_analyzer.rs:327`), reached through delegate dispatch (`src/analyzer/multi_analyzer.rs:109`, `src/analyzer/multi_analyzer.rs:124`).

## Value flow
- The shared builder receives each analyzer's `get_analyzed_files()` set (`src/analyzer/go_analyzer.rs:231`); the underlying implementation collects keys from `state.files` (`src/analyzer/tree_sitter_analyzer.rs:639`). The builder invokes forward resolution for every member using parallel iteration (`src/analyzer/capabilities.rs:71`).
- Reverse-index keys come from `CodeUnit::source()`, which returns the unit's stored `ProjectFile` (`src/analyzer/model.rs:207`); the builder groups importing files under those keys, excludes self references, and deduplicates importers with a `BTreeSet` (`src/analyzer/capabilities.rs:79`).
- Go derives `Clone` (`src/analyzer/go_analyzer.rs:109`), so cloned analyzers share the new `Arc<OnceLock<...>>` (`src/analyzer/go_analyzer.rs:115`). JavaScript also derives `Clone` and stores memo caches behind an `Arc` (`src/analyzer/javascript_analyzer.rs:107`), sharing the lock added inside those caches (`src/analyzer/javascript_analyzer.rs:119`).
- Go's builder callback (`src/analyzer/go_analyzer.rs:232`) reads the forward cache or resolves imports against analyzed file parents (`src/analyzer/go_analyzer.rs:185`). Resolution skips `_` aliases and includes non-module top-level declarations from matching files (`src/analyzer/go_analyzer.rs:193`, `src/analyzer/go_analyzer.rs:210`).
- JavaScript's index callback (`src/analyzer/javascript_analyzer.rs:228`) consumes forward results from `imported_code_units_of` (`src/analyzer/javascript_analyzer.rs:165`); its path resolver accepts relative module paths and probes direct files and directory index files (`src/analyzer/javascript_analyzer.rs:1084`, `src/analyzer/javascript_analyzer.rs:1128`).
- Rust's index callback (`src/analyzer/rust_analyzer.rs:226`) consumes cached units or units found by fully qualified import names (`src/analyzer/rust_analyzer.rs:199`). Name resolution translates `crate`, `super`, and `self` paths into dotted names before declaration lookup (`src/analyzer/rust_analyzer.rs:907`).
- TypeScript's callback (`src/analyzer/typescript_analyzer.rs:242`) consumes its forward resolver's units (`src/analyzer/typescript_analyzer.rs:180`): wildcard imports select non-module declarations; named imports match identifiers, then use module or single-declaration fallback (`src/analyzer/typescript_analyzer.rs:191`, `src/analyzer/typescript_analyzer.rs:208`).
