## Affected callers
- `cpp_expression_type` routes field expressions to `cpp_field_expression_type` (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:7791), whose field candidates now pass through `cpp_unanimous_field_type` (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:7873); these expression types also become call argument types through `cpp_call_argument_types` (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:7749).
- `resolve_cpp_call` passes the function expression directly to `cpp_receiver_type_units` for explicit operator calls (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:5090), reaching the same qualified and subscript receiver arms used for member access (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:7993).
- `cpp_call_return_type` supplies `seeded_bindings` to receiver typing before selecting member candidates (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:10163); the subscript arm forwards those bindings to its argument (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:8018), and the resulting candidates feed unanimous return-type inference (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:10194).
- `cpp_identifier_value_type` calls `cpp_enclosing_member_field_type` only after checking precise local bindings and active shadows (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:8077); enclosing field candidates now use unanimous typing (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:8644).
- The inverse scanner's `declaring_owner_for_explicit_receiver` (crates/bifrost-cpp/src/graph/extractor.rs:8450) and `receiver_has_known_non_target` (crates/bifrost-cpp/src/graph/extractor.rs:8756) both consume receiver units from the walk whose qualified-name arm now calls `qualified_receiver_base` (crates/bifrost-cpp/src/graph/extractor.rs:7898).

## Paths
- `resolve_cpp` dispatches call and field references separately (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:801); calls with a field-expression function converge on `resolve_cpp_field` (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:5124), which reaches the changed receiver arms through `cpp_field_receiver_type_units` (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:6000).
- An empty receiver result from the new qualified arm (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:8009) reaches `resolve_cpp_field`: it first checks external-member evidence, then returns `unsupported_cpp_receiver` when no owner resolved; a resolved owner with no candidates produces `no_indexed_definition` (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:6024).
- Enclosing-field typing submits its owner to `cpp_member_candidates` (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:8643); the underlying lookup searches direct members first and traverses bases when that tier is empty (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:6867).
- Inverse initializer inference supplies a receiver callback with a decremented call-depth budget (crates/bifrost-cpp/src/graph/extractor.rs:769); that callback reaches the shared qualified-name resolution arm (crates/bifrost-cpp/src/graph/extractor.rs:7898), alongside the explicit-receiver navigation route.

## Value flow
- The new qualified-variable arm sends its agreed `CppType` to `cpp_receiver_unit_for_access` (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:7998); that helper uses an alias arrow target when requested and available, otherwise the type's unit (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:8175). The request flag comes from the enclosing field expression's arrow-access detection (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:8164).
- `cpp_unanimous_field_type` obtains types through `cpp_field_declared_type` (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:8040); that constructor reads normalized type text, a resolved unit and indirection from the shared declared-field fact resolver (crates/bifrost-cpp/src/graph/resolver.rs:10833), adds an alias unit and sets `pointee_const` to false (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:7891).
- Both the type agreement check (crates/bifrost-analysis/src/analyzer/usages/get_definition/cpp.rs:8051) and qualified-variable identity check (crates/bifrost-cpp/src/graph/extractor.rs:7764) use `same_visible_symbol` (crates/bifrost-cpp/src/graph/resolver.rs:15056); its logical-symbol branch compares kind, fully qualified name and signature without comparing source files (crates/bifrost-cpp/src/graph/resolver.rs:15121).
- `qualified_receiver_base` collects `GlobalField` candidates (crates/bifrost-cpp/src/graph/extractor.rs:7753) through `named_candidates`, which normalizes the reference and clones matched units (crates/bifrost-cpp/src/graph/resolver.rs:7158); its identity filter accepts fields whose persisted short name contains no dot (crates/bifrost-cpp/src/graph/extractor.rs:7425).
- With no retained global fields, `qualified_receiver_base` returns a type lookup result (crates/bifrost-cpp/src/graph/extractor.rs:7759); `VisibilityIndex::resolve_type` selects the first normalized type candidate (crates/bifrost-cpp/src/graph/resolver.rs:4772). Variable results instead enter the inverse's `receiver_units_from_declared_fields` (crates/bifrost-cpp/src/graph/extractor.rs:7900), which resolves each declaration and reduces the units to one visible symbol (crates/bifrost-cpp/src/graph/extractor.rs:8318).
