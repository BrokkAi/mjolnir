## Paths

- CLI `run_engine` constructs either a persisted or ephemeral workspace and calls the progress-enabled audit (`src/bin/bifrost_reference_differential.rs:787`, `src/bin/bifrost_reference_differential.rs:796`); that audit selects external forward processing from the config (`src/reference_differential/mod.rs:726`).
- The external frontier uses `reference_candidate_ranges` (`src/reference_differential/mod.rs:1073`), then passes through the existing priority calculation and bounded heap using `config.max_sites` (`src/reference_differential/mod.rs:1254`). Boundary eligibility is evaluated later, during forward resolution (`src/reference_differential/mod.rs:1523`).
- Per-file external processing runs inside the existing Rayon pool (`src/reference_differential/mod.rs:1299`, `src/reference_differential/mod.rs:1305`). After those calls return, the audit checks the shared query scope before grouping targets or entering inverse comparison (`src/reference_differential/mod.rs:728`); scope store errors become a returned string (`src/reference_differential/mod.rs:1992`).
- External file results return an empty resolved-target vector (`src/reference_differential/mod.rs:1572`); the audit groups that vector (`src/reference_differential/mod.rs:730`), and inverse comparison returns before constructing usage-query state when no prepared groups exist (`src/reference_differential/mod.rs:1818`).

## Value flow

- Each external outcome increments the existing forward-status counters before boundary filtering (`src/reference_differential/mod.rs:1522`, `src/reference_differential/mod.rs:3165`). Excluded outcomes increment the per-file counter, which is added to `summary.external_ineligible_sites` (`src/reference_differential/mod.rs:1524`, `src/reference_differential/mod.rs:1326`); `summary.sampled_sites` was assigned before this filtering (`src/reference_differential/mod.rs:713`).
- External requests take byte ranges and point-lookup flags from sampled sites (`src/reference_differential/mod.rs:1510`), whose flags originate in `reference_candidate_requires_point_lookup` (`src/reference_differential/mod.rs:1245`). The traced batch wrapper supplies a fresh cancellation token (`crates/bifrost-analysis/src/analyzer/usages/get_definition/mod.rs:704`) and returns outcome/trace pairs consumed by the external loop (`src/reference_differential/mod.rs:1520`).
- The classifier's verdict is stored on the site (`src/reference_differential/mod.rs:1558`), then counted by `recompute_classifications` (`src/reference_differential/mod.rs:3148`). The report's actionable total reads those counts (`src/reference_differential/mod.rs:218`), and CLI strict mode consumes `has_actionable_findings` (`src/bin/bifrost_reference_differential.rs:532`).
- The classifier reads each route's boundary, target, and selection (`src/reference_differential/mod.rs:1621`). Their producer, `finish_boundary`, obtains boundary evidence, stamps rows initially marked `ExternalUnknown`, and selects external routes with an indexed boundary and a named target (`crates/bifrost-analysis/src/analyzer/usages/get_definition/trace.rs:739`).
- The classifier's direct evidence call uses the trace route name (`src/reference_differential/mod.rs:1624`). For Java, the shared evidence function supplies the dispatching analyzer's overlay (`crates/bifrost-analysis/src/analyzer/usages/get_definition/trace.rs:796`); Java returns an external type/member FQN, or an unindexed/unknown boundary with no target (`crates/bifrost-analysis/src/analyzer/java/mod.rs:259`).
- Both quality values compared by the classifier use the same forward status with different boundary inputs (`src/reference_differential/mod.rs:1625`). For a boundary outcome, the mapping yields `Complete` for local/indexed, `Unproven` for declared-unindexed, and `Unknown` for unknown/absent boundaries (`crates/bifrost-analysis/src/analyzer/usages/get_definition/trace.rs:1021`).
