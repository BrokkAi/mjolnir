- [P1] Preserve implicit external supertypes after a complete empty lookup — crates/bifrost-analysis/src/analyzer/resolution/selected_context.rs:1567-1568
  When a Java class extends an implicitly imported external type such as `Thread` and structured lookup returns complete with no targets, this now hides its fallback from `cached_hierarchy_reference_parts`, which uses this accessor and consequently returns an empty, complete supertype set. Even when the JDK owner is indexed, inherited members and subtype relationships are lost; the hierarchy lookup needs to consider the fallback after checking the selected answer, just as the type projection does.
