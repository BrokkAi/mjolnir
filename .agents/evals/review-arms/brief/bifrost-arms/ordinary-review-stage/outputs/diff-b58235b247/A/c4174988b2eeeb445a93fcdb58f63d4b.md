- [P1] Follow Python's method resolution order for multiple inheritance — crates/bifrost-python/src/graph/resolver.rs:59-62
  For `class C(A, B)` where both bases define the same member, Python selects the first declaration in C's C3 method resolution order, but this returns both declarations at the same breadth-first layer. It can also select a nearer declaration in a later base over an inherited declaration in an earlier base. Consequently usage queries and graph edges attribute calls to the wrong methods and omit the actual method in the latter case.

- [P2] Resolve the bound root of an unaliased dotted import — crates/bifrost-analysis/src/analyzer/usages/get_definition/python.rs:1966-1969
  For a function containing `import pkg.sub` followed by a reference to `pkg`, Python binds `pkg` to the root package, but the new lookup resolves the binding's full `pkg.sub` qualified name. Definition navigation therefore reports the submodule for the root identifier; `consumed_attributes` already distinguishes this import form.

- [P2] Honor inner import shadowing before selecting an outer binding — crates/bifrost-analysis/src/analyzer/usages/get_definition/python.rs:1946-1951
  When an enclosing function imports a name and an inner function imports the same name later in its body, a reference before the inner import is an unbound local in Python. This search skips the later inner import and selects the enclosing one, while the subsequent inventory check does not treat an import as a runtime write, so navigation incorrectly resolves the reference to the outer import.
