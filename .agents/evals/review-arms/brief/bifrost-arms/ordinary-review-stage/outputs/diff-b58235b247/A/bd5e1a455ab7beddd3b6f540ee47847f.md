- [P2] Follow Python's method resolution order for multiple inheritance — crates/bifrost-python/src/graph/resolver.rs:55-64
  When a class inherits from multiple bases, Python uses C3 method resolution order rather than the nearest breadth-first layer. For example, with `class C(A, B)` where `A` inherits `save` from a parent and `B` declares `save`, `C().save()` selects the inherited `A` member, but this search stops at `B` and attributes the call to the wrong declaration. Two direct bases declaring the member similarly produce both declarations instead of selecting the first.

- [P2] Account for writes inside the reference's enclosing statement — crates/bifrost-python/src/imports.rs:48-52
  When a reference is nested in a compound statement, this stops before inspecting any earlier writes in that statement. For example, after `canonical = importlib.import_module("pkg.mod")`, an `if` body containing `canonical = other` followed by `canonical.target()` is still attributed to `pkg.mod.target`, although the reassignment always precedes that reference. This creates false usage and graph edges for the imported module.

- [P2] Resolve the actual local binding of dotted imports — crates/bifrost-analysis/src/analyzer/usages/get_definition/python.rs:1966-1969
  For a function-local `import pkg.submodule` without an alias, Python binds `pkg`, while the recorded qualified name is `pkg.submodule`. The new early return therefore resolves a reference to `pkg` to the submodule instead of the package, including the root of `pkg.submodule` expressions. The binding's consumed attribute count must be considered when resolving the identifier.
