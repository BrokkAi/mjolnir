- [P2] Respect Python's method resolution order for multiple inheritance — crates/bifrost-python/src/graph/resolver.rs:59-65. When multiple bases declare the same member, returning every declaration in the first breadth-first layer attributes a call to all of them, although Python selects the first declaration in its C3 method resolution order. Breadth-first traversal can also select a later base over an earlier base's ancestor, so both usage results and inverted edges are incorrect for ordinary multiple-inheritance hierarchies.
- [P2] Honor inner function declarations before outer imports — crates/bifrost-analysis/src/analyzer/usages/get_definition/python.rs:1945-1951. If an outer function imports a name and an inner function declares a function with that same name, the outer import passes this scope-range check and `has_runtime_callable_binding_at` does not treat a function-only declaration as a runtime binding. Navigation on the inner call therefore returns the imported symbol instead of the inner function, bypassing the existing lexical resolution path.
- [P2] Check importlib rebinding before accepting the receiver — crates/bifrost-python/src/graph/extractor.rs:536-543. When a function imports `importlib` and subsequently reassigns that local before calling `importlib.import_module`, this selects the earlier import solely by its range and reports the resulting module member as a usage even though the receiver now refers to another object. The binding must be valid at the assignment site, including intervening writes.
