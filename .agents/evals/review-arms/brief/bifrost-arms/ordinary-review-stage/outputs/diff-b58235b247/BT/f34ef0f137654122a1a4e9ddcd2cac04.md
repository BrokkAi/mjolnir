- [P1] Follow Python's method resolution order for inherited members — crates/bifrost-python/src/graph/resolver.rs:59-65. In multiple inheritance, breadth-first layers do not match Python's C3 method resolution order. For example, with `B(A)`, `D(B, C)`, and `save` declared on both `A` and `C`, `D().save()` resolves to `A.save`, but this code selects `C.save`; it also returns both declarations when two direct bases define the member. Usage queries and graph edges therefore omit the actual target and attribute calls to unrelated overrides.
- [P2] Invalidate imported modules after nested or destructuring writes — crates/bifrost-python/src/imports.rs:71-74. If a direct literal import is followed by `if condition: canonical = other` or `canonical, x = other, 1`, the binding collector is called only on the outer statement and does not traverse its body or the expression wrapper. The earlier module remains selected, so `canonical.member` is reported as a definite usage of the imported module even when the receiver has been reassigned.
- [P2] Respect an inner function's local binding before selecting an outer import — crates/bifrost-analysis/src/analyzer/usages/get_definition/python.rs:1946-1952. When an outer function imports `Worker` and an inner function references `Worker` before its own later `from other import Worker`, this search selects the outer import because the inner import occurs after the reference. Python treats `Worker` as local throughout the inner function, so the reference raises `UnboundLocalError`; navigation instead incorrectly resolves it to the outer target.
