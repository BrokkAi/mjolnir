- [P2] Substitute template parameters in qualified pointee types — src/analyzer/usages/get_definition.rs:7385-7392. When a wrapper declares `const T* operator->()`, the extracted pointee is `const T`, so the exact equality check never substitutes `T` with the alias argument. Resolving that text then fails, and valid accesses through an alias such as `using P = Wrapper<Node>` no longer resolve to members of `Node`; the previous first-argument behavior handled this case.
- [P2] Follow class-valued operator-> results — src/analyzer/usages/get_definition.rs:7360-7363. C++ permits `operator->` to return another class with its own `operator->`, and applies the operator repeatedly until it reaches a pointer. A wrapper returning such a proxy now fails this pointer-depth check, so accesses through aliases to that wrapper lose the member resolution that previously worked when the first template argument was the ultimate pointee.
- [P2] Apply default template arguments during substitution — src/analyzer/usages/get_definition.rs:7387-7392. For `template<class T, class U = T> struct Wrapper` with `U* operator->()` and `using P = Wrapper<Node>`, the second parameter has no corresponding explicit argument, so `U` is left unresolved even though its default is `Node`. Valid member accesses through `P` therefore regress from the previous first-argument resolution.
