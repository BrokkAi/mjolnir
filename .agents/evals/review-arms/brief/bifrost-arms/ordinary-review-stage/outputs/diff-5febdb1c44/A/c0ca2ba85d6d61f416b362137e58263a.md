- [P2] Substitute template parameters inside qualified return types — src/analyzer/usages/get_definition.rs:7390-7394
  When a wrapper declares `const T* operator->()`, the pointee text is `const T`, so the exact-string comparison does not substitute `T` and the resolver cannot find the actual class. A valid access such as `using P = Wrapper<Node>; P p; p->member()` therefore stops resolving even though the previous first-argument handling resolved it.
- [P2] Resolve pointer return aliases before checking pointer depth — src/analyzer/usages/get_definition.rs:7362-7363
  When `operator->` returns a named pointer type, such as `using pointer = T*; pointer operator->()`, its declared return text contains no `*`, so this check rejects the operator and member lookup falls back to the wrapper. This breaks valid smart-pointer aliases that use a `pointer` typedef, including wrappers whose pointee was previously resolved from the template argument.
- [P2] Follow proxy objects returned by operator arrow — src/analyzer/usages/get_definition.rs:7362-7363
  When `operator->` returns a proxy object that itself defines `operator->`, C++ applies the operator repeatedly until a pointer is reached. Rejecting every non-pointer return here makes valid `Wrapper<Node>` aliases with such a proxy lose member resolution, even when the proxy ultimately returns `Node*` and the previous handling resolved the member.
