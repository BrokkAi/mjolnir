- [P2] Substitute template parameters in qualified pointee types — src/analyzer/usages/get_definition.rs:7370-7371
  When `operator->` returns `const T*` or `volatile T*`, the pointee text is `const T` or `volatile T`, so the exact-match substitution leaves `T` unresolved. For example, `using Ptr = Wrapper<Node>;` with `const T* operator->() const` no longer resolves `ptr->member`, although the previous first-argument behavior did. Substitute the parameter within the qualified type before resolving it.

- [P2] Use default template arguments when resolving the return type — src/analyzer/usages/get_definition.rs:7389-7393
  When an omitted template argument has a default, the parameter has no corresponding entry in `args`, so it is left unresolved. For example, `template<class T, class U = T> class Wrapper { U* operator->(); }; using Ptr = Wrapper<Node>;` makes `ptr->member` fail to resolve even though `U` is `Node` and the previous implementation resolved it. Resolve omitted arguments from the wrapper's defaults, including defaults that refer to earlier parameters.

- [P2] Do not search wrapper members when arrow resolution fails — src/analyzer/usages/get_definition.rs:6425-6429
  For an alias to a non-pointer wrapper with no `operator->` (or an operator returning a non-pointer), the new helper returns `None` and this falls through to the wrapper class. Consequently `x->size()` can resolve to the wrapper's `size` member even though the expression is invalid; this is newly observable for aliases such as `using X = Container<Node>`, which previously searched `Node`. Distinguish a failed overloaded-arrow lookup from an ordinary pointer receiver and avoid returning the wrapper as the arrow target.
