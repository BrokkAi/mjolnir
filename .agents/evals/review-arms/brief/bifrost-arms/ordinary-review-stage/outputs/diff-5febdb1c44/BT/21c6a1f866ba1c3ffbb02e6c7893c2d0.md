- [P2] Substitute template parameters inside qualified pointee types — src/analyzer/usages/get_definition.rs:7370-7371 — When an operator returns a qualified template parameter, such as `const T* operator->()`, the extracted pointee is `const T`, which does not equal the parameter name `T`. Substitution therefore never happens and resolution of `ptr->member` fails, even though the previous first-argument handling resolved this common smart-pointer shape.
- [P2] Follow alias chains before extracting wrapper arguments — src/analyzer/usages/get_definition.rs:7346-7347 — For `using Ptr = Wrapper<Node>; using Alias = Ptr;`, the receiver's alias is `Alias`, so this reads `Ptr` as the wrapper head and collects no arguments. Resolving the head follows the alias to `Wrapper`, but its `T` cannot be substituted and `Alias::operator->` member resolution fails; the template arguments need to be retained while following the alias chain.
- [P2] Avoid looking up arrow members on a wrapper without an operator — src/analyzer/usages/get_definition.rs:6421-6426 — If an alias names a class with no `operator->` (or one returning a non-pointer), the new resolver returns `None` and this falls back to the wrapper class. Consequently `obj->size()` can resolve to the wrapper's `size` member even though the expression is invalid C++; failed arrow resolution must not be treated as ordinary member access on the wrapper.
