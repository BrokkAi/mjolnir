- [P1] Preserve procedure ownership for trailing deletions — crates/bifrost-policy/src/taint_policy.rs:1525-1528. When the last statement of a Python function is deleted, the zero-width head hunk falls after the remaining function node's end (at the next line or EOF), so this strict interior test excludes the edited function. Any remaining sinks in it are omitted and the run can report a complete empty result. Resolving deletion ownership requires the base-side procedure range as well as the head position.
- [P2] Exclude nested edits from synthetic module-body scope — crates/bifrost-policy/src/taint_policy.rs:1529-1530. JavaScript and TypeScript files with top-level statements have a synthetic module-body procedure whose span is the entire program, including function declarations. Consequently, editing a function or even a module comment overlaps that procedure and admits unrelated top-level sinks, recreating the unrelated-sink and inconclusive-result problem this change is intended to prevent.
