- [P1] Preserve cross-file definition ordering in index invalidation crates/bifrost-store/src/analyzer/store/mod.rs:13099-13103
  When two matching definitions are in different files, shifting one declaration can change their relative order even though each file's declaration order and semantic fields stay the same. `definition_sort_key` orders candidates by `first_start_byte` before the file tie-breaker, so dropping the range input makes the index digest unchanged while a fresh `definitions` lookup returns the candidates in the opposite order. A reused policy unit can therefore retain a result based on the wrong definition; the read key must capture the ordering actually exposed by the lookup, or the lookup ordering must be made position-independent.
