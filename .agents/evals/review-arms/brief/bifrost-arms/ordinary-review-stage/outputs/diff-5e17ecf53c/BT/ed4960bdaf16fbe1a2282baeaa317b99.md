- [P2] Stop recovery at the end of a normal macro definition — src/analyzer/usages/get_definition/cpp.rs:3967-3970
  When a normal function-like macro is immediately followed by an unrelated malformed declaration or expression, an identifier inside that wrapper's `ERROR` node is classified as part of the macro. The loop accepts any preceding `preproc_function_def` with a value, without establishing that its recovery actually extends into the following wrapper. For example, while editing an incomplete declaration immediately after `#define F(x) x`, references in its error node can return `declaration_or_import_site` instead of resolving. A clean intervening declaration avoids the problem, so the new boundary test does not cover this case.
