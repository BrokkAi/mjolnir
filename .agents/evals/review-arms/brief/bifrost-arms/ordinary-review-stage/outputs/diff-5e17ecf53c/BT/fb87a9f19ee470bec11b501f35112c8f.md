- [P2] Stop recovery at the end of a valid macro definition — src/analyzer/usages/get_definition/cpp.rs:3963-3968
  When an ordinary function-like macro is followed immediately by an unrelated malformed declaration or expression containing a reference inside an `ERROR` node, this walk reaches the macro and classifies that reference as part of its replacement text. The macro need only have a value; there is no check that the erroneous wrapper actually continues its source line. Consequently, go-to-definition returns `declaration_or_import_site` for unrelated code while it is being edited, even when the preceding macro is completely valid.
