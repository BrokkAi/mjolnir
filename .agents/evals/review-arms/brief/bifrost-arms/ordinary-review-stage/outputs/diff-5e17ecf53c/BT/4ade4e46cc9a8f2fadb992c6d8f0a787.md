- [P2] Do not attribute unrelated malformed declarations to a preceding macro — src/analyzer/usages/get_definition/cpp.rs:3965-3966 — When a normal function-like macro is immediately followed by a malformed declaration or expression whose identifier is inside an `ERROR` node, the new wrapper traversal reaches the macro and classifies that identifier as part of its body. The macro only needs to have a value; neither a malformed macro nor a continued preprocessor line is required. As a result, go-to-definition incorrectly returns `declaration_or_import_site` for unrelated code being edited after an otherwise valid macro. The clean-declaration boundary test does not cover this case because there is no clean sibling between the macro and the malformed code.
