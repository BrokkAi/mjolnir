- [P2] Stop recovery at the actual end of the macro — src/analyzer/usages/get_definition/cpp.rs:3964-3969
  When an ordinary function-like macro is immediately followed by a malformed declaration containing a reference inside an `ERROR` node, this scan treats that declaration as a macro recovery tail solely because it has an error and follows a macro. For example, in `int keep;\n#define F(x) x\nint later = keep keep;`, the erroneous declaration is independent of the completed macro, but the reference inside its recovery node is reported as a non-reference. The same happens after any sequence of erroneous top-level wrappers, so incomplete code being edited can lose definition navigation even when the preceding macro was parsed correctly.
