- [P2] Preserve generic arity when matching C# selectors — src/analyzer/symbol_lookup.rs:400-406
  When a selector specifies an arity that differs from the declaration, such as `Widget`2` for `Widget<T>`, stripping the suffix resolves the wrong type instead of reporting no match. The same problem affects generic methods and can also conflate types with different numbers of type parameters; the metadata arity needs to participate in matching against the declaration.
- [P2] Apply the file anchor before rejecting ambiguous Lombok owners — src/searchtools.rs:2404-2406
  If two packages contain an annotated `Widget` and the request is `path/to/Widget.java#Widget.getName`, owner lookup finds both fully qualified names and returns no source before the anchor can narrow the candidates. Consequently a valid file-qualified generated accessor fails precisely when the anchor is needed to distinguish owners; filter owners by the anchor before testing their uniqueness.
- [P2] Avoid a workspace-wide scan for every Java parent lookup — src/analyzer/java/mod.rs:273
  `structural_parent_of` linearly scans the analyzer's entire children map (and potentially all module declarations), whereas Java parent lookup is invoked for each enclosing usage context. Scanning usages in a large Java workspace therefore multiplies the number of references by the number of declarations, causing a substantial regression on a hot path; structural parents need an indexed lookup.
