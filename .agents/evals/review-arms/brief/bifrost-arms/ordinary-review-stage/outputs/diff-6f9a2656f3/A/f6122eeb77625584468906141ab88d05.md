- [P2] Avoid retaining every resolved import set during index construction — src/analyzer/capabilities.rs:71-74. On a large repository, this collects the resolved `CodeUnit` sets for every file before constructing any reverse edges, so peak memory scales with the total number of imported declarations rather than the much smaller number of file-to-file edges. This is especially costly for Go packages with many declarations imported by many files, and can exhaust memory even when the final reverse index is modest; the previous scan held only one candidate's resolved set at a time.
- [P2] Preserve cheap filtering for the first JavaScript reverse lookup — src/analyzer/javascript_analyzer.rs:226-229. When only one or a few targets are queried, the first lookup now fully resolves imports and fetches declarations for every JavaScript file in the repository. Previously `could_import_file` filtered candidates by the requested target before performing that resolution, so large repositories with sparse references can spend substantially more time and memory on a single lookup, including the single-seed CLI use case.
