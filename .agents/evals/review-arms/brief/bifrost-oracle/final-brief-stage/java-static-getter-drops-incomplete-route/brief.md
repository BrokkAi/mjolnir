## Paths
- Forward Java lookup and inverse confirmation both reach the modified context composer: `java_import_context` adds the open-inventory wrapper, while `java_reverse_import_context` returns the composition directly (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:297, crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:310, crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:400). Hierarchy confirmation invokes the reverse dispatcher for each candidate file (crates/bifrost-analysis/src/analyzer/store/resolution_operation/java_reverse_rows.rs:871).
- Alias resolution checks source-set access and declaration access before the new Kotlin binary-owner walk (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:2393, crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:2419). That walk reuses `jvm_declaration_access`, which excludes private declarations and cross-package protected/package-private declarations (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:3716).
- Static aliases attach an exact definition to their bridge (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:2567). Path construction consumes that field by ending at the definition with an empty export stack and a definition-node witness (crates/bifrost-analysis/src/analyzer/resolution/selected_context.rs:3410).
- The Java static-import branch adds alias and ordinary member bridges together (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:3182); ordinary static-member handling separately checks enclosing-instance construction requirements before accepting type-access candidates (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:5281).
- The new golden renderer delegates comparison to `check_golden_case` (tests/suite_semantic/golden_java_static_kotlin_imports.rs:20); that helper reads `expected.txt`, normalizes CRLF, and compares it with the renderer output, or rewrites it when `BIFROST_BLESS=1` (tests/common/golden.rs:61).

## Value flow
- The alias reader's added `is_static` column (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:80) comes from prepared alias rows that store `fact.is_static` alongside kind, name and status (crates/bifrost-analysis/src/analyzer/store/resolution_prepare.rs:766). The same preparation stores owner segments in ordinal order (crates/bifrost-analysis/src/analyzer/store/resolution_prepare.rs:775).
- The new declaration-gap query uses `covers=6` for the declaration and `covers=5` for binder starts (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:99); these values are the persisted reverse- and forward-endpoint codes (crates/bifrost-analysis/src/analyzer/store/resolution_prepare/resolution_rows.rs:614). Its reason IDs become target-mount-local `UnsupportedSemantic` reasons in bridge completion (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:2527).
- Kotlin extraction marks top-level callable aliases static and emits an additional static method alias for `@JvmStatic`, using a companion's enclosing type or the object itself as owner (crates/bifrost-jvm/src/kotlin/resolution.rs:2185, crates/bifrost-jvm/src/kotlin/resolution.rs:2194). The reader compares those owner segments with the import route and admits static methods only for Callable demands, and static fields/singleton aliases for Value demands (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:2333).
- Kotlin property extraction emits `ResolutionJvmAliasKind::Getter` with `is_static` set from `top_level` (crates/bifrost-jvm/src/kotlin/resolution.rs:2309), targeting the property declaration in the Value namespace (crates/bifrost-jvm/src/kotlin/resolution.rs:1487); the alias reader compares the resulting kind and static flag with the import demand namespace (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:2339).
- `found_alias` is set after owner/static/namespace matching and before status and accessibility checks (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:2350). Its returned value adds the member name to `indexed_static_import_members` (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:3164); the existing final filter removes external-static boundaries whose member appears in that collection (crates/bifrost-analysis/src/analyzer/store/resolution_operation/jvm_context.rs:3495).
