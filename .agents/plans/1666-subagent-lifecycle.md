# Epic #1666: Sub-agent lifecycle, teardown, load resilience, and parent authorization

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

This document must be maintained in accordance with `.agents/PLANS.md` in the repository root.

## Purpose / Big Picture

Epic `#1666` addresses four remaining defects in how Mjolnir manages delegated sub-agents across their full lifecycle (spawn, startup under host load, mid-task steering, and teardown):

1. **Borrowed child disk bloat and transcript lifecycle (`#1602`):** Today, closing or destroying a borrowed sub-agent (a child running inside its parent's container or bare workspace without its own container/environment) stops its worker process but leaves `/var/lib/hel/{workers,profiles}/<child-id>` (or the bare-host equivalents) behind on disk until the parent itself is eventually suspended or destroyed. Furthermore, previously closed borrowed children keep their SQLite transcript rows and spilled tool-detail `.mjtd` files indefinitely even after their parent is suspended or moved to another target. After Milestone 1, closing, destroying, or cleaning up a failed borrowed child immediately removes its private worker and profile directories while keeping its SQLite transcript inspectable while the parent is alive, and suspending (or cross-target moving) the parent atomically purges all remaining closed borrowed children's transcripts while preserving standalone orchestrator children (those that own their own environment/container) indefinitely.
2. **False startup failure leaving busy children running (`#1431`):** Today, the daemon seeds initial configuration commands and the spawn brief directly into the child worker's durable FIFO queue, then watches delayed database projections with a hard 60-second deadline. Under heavy load, if the worker takes longer than 60 seconds to finish applying config or publish prompt acceptance, the daemon fabricates a startup rejection, marks the child failed in the store, reports `State: error` to the parent, and calls `park`, which sees the child is busy and leaves it running and editing the shared worktree. After Milestone 2, a live worker that already owns its seeded FIFO is never falsely rejected on a projection timeout, and any genuinely rejected startup stops and confirms the worker dead before marking the child `Error` or notifying the parent.
3. **Host-load resilience for `list_agents`, `spawn`, and relay/startup timeouts (`#1438`, incorporating `#1363`):** Under heavy host load, `list_agents` queues behind `spawn` in the shared 32-slot general dispatch lane, executes serialized SQLite writes and parent lifecycle lease waits, and times out at 120 seconds—leaving parents blind to whether timed-out spawns succeeded. Meanwhile, fixed 15-second relay RPC timeouts fail slow status/queue calls and the 300-second worker native-open timer ignores monotonic startup progress. After Milestone 3, `list_agents` runs on its own fast read lane without waiting behind `spawn` or unnecessary SQLite write phases, timed-out `spawn` replies return structured request-ID guidance correlated with `list_agents` before and after registration, slow status/queue RPCs tolerate host load without abandoning healthy workers, and worker native-open stall accounting resets on genuine monotonic startup milestones.
4. **Parent `send_message` authority in child auto-review (`#1405`):** Today, both Mjolnir's own ACP Guardian and Codex app-server's native `auto_review` Guardian can reject mid-task instructions sent by a child's parent via `send_message` as "untrusted authorization" (for Mjolnir Guardian, verified `ParentMessage` deliveries and even the spawn brief are excluded from person-authorization evidence; for Codex, active-turn mailbox mail is delivered through `PostToolUse.additionalContext`, which Codex's native Guardian excludes from trusted user input). After Milestone 4, Mjolnir's ACP Guardian recognizes daemon-verified `ParentMessage` deliveries (and the initial spawn brief) as delegated parent authorization while keeping peer messages strictly untrusted, and Codex routes verified `ParentMessage` events through its native `UserInput` channel (`_session/steering` / `turn/steer` when active on steer-safe providers, parent-only `UserInput` prompt when idle, preserving direct DeepSeek turn-boundary ordering).

Each milestone is independently testable, reviewed through `mj-review`, committed to `master`, and pushed as its own validated checkpoint.

## Decision Log

- Decision: Keep closed borrowed children's SQLite transcripts and `.mjtd` tool details while the parent is alive, delete `/var/lib/hel/{workers,profiles}/<child-id>` (and bare equivalents) immediately upon borrowed child `close` / `Destroy` / failed-start cleanup, and atomically purge remaining closed borrowed children's transcripts when the parent commits `suspend` or cross-target `Move` (while keeping standalone orchestrator children's transcripts indefinitely).
  Rationale: Explicitly requested by the user on 2026-11-23 so a parent/operator can still examine a closed child's transcript during the parent's lifetime without leaking multi-GB container disk layers (`#1602`) or accumulating dead child transcripts after the parent suspends.
  Date/Author: 2026-11-23 / user + coordinator.

- Decision: Scope borrowed-transcript purging on parent suspend and cross-target Move to the retiring owner's own borrowed subtree and historical borrowed bindings, stopping recursion at any standalone orchestrator child (`owns_environment == Some(true)`).
  Rationale: An orchestrator child owns an independent container/environment that can outlive a cross-target Move or survive a failed orchestrator suspend during parent suspend. Its own borrowers belong to its own suspend/Move lifecycle, so we never delete transcripts of live independent branches.
  Date/Author: 2026-11-23 / coordinator.

- Decision: Retain `environment_workers` ledger rows on borrowed child `close` in Milestone 1 (preserving `770a4e74c` physical cleanup invariants), and leave filesystem-only unknown directories in live containers to parent container retirement rather than adding a live container directory scan.
  Rationale: `environment_workers` has no foreign key to `sessions` and guarantees physical teardown across logical deletes and startup retries. Removing worker and profile directories cleanly on `close`, `Destroy`, and failed-start cleanup stops new orphans from being created without introducing risky live-container heuristics that could delete active work.
  Date/Author: 2026-11-23 / coordinator.

- Decision: For Milestone 2 (`#1431`), reuse the existing `WorkerHarnessStartupFailure` typed exit record (`worker-exit.json` + `mj-session-runtime/src/session_manager/recovery.rs`) when a required seeded `SetConfig` fails in `mj-worker`, instead of keeping a rejected worker alive behind a FIFO fence or adding schema revision 154 (`api_config_dispositions`).
  Rationale: An earlier attempt that kept rejected workers alive, suppressed `CommandInterrupted` in projection, added `CommandQueued(insert_at_front)` retries, added schema revision 154, and hid legacy failed rows in `api.rs` grew to 30 files / +1,980 lines and drew P1 review findings in three consecutive rounds — all in self-added state. Returning `WorkerHarnessStartupFailure` from `ensure_initial_commands_succeeded()` guarantees the worker exits before promoting the brief, existing daemon recovery confirms death and sets `Error` without looping restarts, and removing the 60 s observation deadline (plus refusing to persist `fail_startup_group` when `stop_idle_subagent` returns `ParkOutcome::Busy`) eliminates `#1431` in ~5 files with zero schema migration or new lifecycle kinds.
  Date/Author: 2026-11-23 / user + coordinator.

- Decision: Do not add an unmeasured speculative static concurrency cap for bare-host spawns in Milestone 3.
  Rationale: `AGENTS.md` forbids speculative caps without measured limits; `mj-controller/src/controller/provisioning.rs:54-94` already documents that 4 concurrent bare starts ran in ~2.8 s whereas shared Podman containers contended at 2. Focus Milestone 3 on eliminating the real measured bottlenecks (`list_agents` lane/SQLite/lease contention, ambiguous `spawn` timeout replies, short 15 s relay RPC failures on slow status/queue reads, and elapsed-only worker native-open stall detection).
  Date/Author: 2026-11-23 / coordinator.

- Decision: For `#1405`, preserve native Codex `auto_review` ownership and route only daemon-verified `ParentMessage` events through Codex `UserInput` (`_session/steering` when active on steer-safe providers, parent-only `UserInput` prompt when idle), excluding them atomically from `PostToolUse.additionalContext` and never mixing untrusted `PeerMessage` text into parent `UserInput`, while preserving direct DeepSeek turn-boundary ordering (`#1455`/`#1492`).
  Rationale: Switching Codex to `workspace-write` would alter sandbox selection and drop native reviewer coverage; routing verified parent events over Codex's existing `_session/steering` / `UserInput` channel gives native Guardian the exact same user-input provenance as the initial spawn brief without weakening peer isolation.
  Date/Author: 2026-11-23 / coordinator.

Key terminology used throughout this plan:
- **Borrowed child (borrowed worker):** A sub-agent that executes inside its parent's existing container or bare workspace rather than owning a dedicated container/clone. Durably identified by `owns_environment == Some(false)` (equivalently, its environment's `owner_session_id != child_session_id`).
- **Orchestrator child (standalone child):** A sub-agent that owns its own dedicated container/clone/environment (`owns_environment == Some(true)`). Its lifecycle and transcript survive parent suspend independently.
- **Worker root and profile directory:** The per-session runtime directory (`/var/lib/hel/workers/<id>` in containers, `.local/share/hel/workers/<id>` on SSH bare, or the recorded sibling worker root on local bare) and per-session harness profile copy (`/var/lib/hel/profiles/<id>` or `<data_dir>/profiles/<id>`).
- **Seeded initial FIFO:** Since commit `68d5bbd55`, child launch configuration (`mj-worker-launch/src/worker_launch.rs`) hands the child's required config commands, optional config commands, and initial spawn brief to the worker so the worker journals them in its relay FIFO before publishing its control socket.
- **MBX build shim:** This checkout's `target` directory is a symlink managed by `mbx` (`/home/jonathan/.local/share/mbx/bin/cargo` is on `PATH`). Run normal `cargo test` / `cargo clippy` (which invoke the `mbx` shim) without overriding `CARGO_TARGET_DIR`, and run tests outside the sandbox with elevated permissions so loopback TCP and Unix sockets work.
