# Let the TUI exit after daemon-owned work is accepted

This ExecPlan is maintained according to `.agents/PLANS.md`. Its progress, findings, decisions and outcomes must reflect the current implementation and evidence.

## Purpose / Big Picture

Suspending a session can require a checkpoint and cleanup that outlive the dashboard. Once the daemon has accepted responsibility, closing the TUI must not wait for that operation to finish. The operation must continue after the client disconnects, and its eventual result must remain visible to a later client. A request that has not reached the daemon and a draft that has not been saved still belong to the TUI; exiting must not silently lose them.

The immediate report is a suspend of session 5bc0d90883ed581d402cf1eee88b4a2f taking multiple minutes. Explain its measured lifecycle phase separately from the TUI's exit wait. Audit other operations against the same ownership boundary and correct any shared lifecycle wait rather than adding a suspend-only exception.

## Surprises & Discoveries

The previous quit improvement in #1486 made drafts incremental and overlapped final settings/session-manager cleanup. Its recorded shutdown order still drains pending mutations before detaching. Whether that drain waits for operation acceptance or complete checkpoint execution is the current investigation; do not assume that all tasks in a background registry have the same owner.

The prior global idle-goal correction, old-worker admission bootstrap and node removal were installed and live verified before this report. Their tests do not establish that the TUI's request future ends at the daemon ownership boundary.

For the observed suspend, the worker answered Idle in 22ms and checkpoint export finished at 21:31:39 UTC after 6927ms. The retiring environment contains 93 distinct worker roots, with the parent Destroying and 92 child records Stopped. Reclamation::acquire stops every root serially; 93 successful commands consumed 464557ms through 21:39:36. Reclamation::remove_targets then executes standalone cleanup plans that stop them again before removal; 19 second-pass commands consumed another 106194ms by 21:41:25. Logical Stopped does not prove that physical processes are absent, and the measured per-call cost is not evidence of an unconditional five-second timeout.

The TUI event loop is not blocked by the suspend call. Its quit drain waits for the CriticalOperationTracker guard held through the full synchronous reply. Suspend, Restart, Resume, DiscardSinceCheckpoint and Destroy share that completion wait. Quit sets lifecycle cancellation flags, and Move/RetryMove respond by sending CancelLifecycle. Existing creation and archive restoration already release their quit guards at RegisteredSession. Container upgrade already returns after durable admission, but its TUI request is unguarded before that receipt. Resume repository preflight is a read that unnecessarily holds a critical guard. Drafts, read status, settings/local preferences and import bytes are different: they remain client-owned until their save or handoff completes.

The daemon lifecycle owner already atomically registers active operations and retains completed results in a bounded FIFO. Container upgrade already supplies a useful pattern: the admitted callback persists and binds its restart intent, sends an acceptance oneshot, and continues under daemon ownership. HTTP Move already starts lifecycle admission before returning Accepted. HTTP Suspend durably prepares Closing before returning Accepted, then invokes its supervised action; unify that with the shared start boundary instead of adding another queue.

Native macOS fixtures proved that both `ps eww` and `ps -E` flatten arguments and environment values without preserving their boundaries. An unrelated process with `MJ_SESSION_ID=<id>` as an argument or inside another environment value was falsely attributed by word matching. Linux's exact NUL-delimited environment comparison does not have this defect. Darwin's native KERN_PROCARGS2 reader preserved the necessary boundaries in the fixture; the unsafe shell word matcher must be removed before delivery.

A second ownership check showed that the entire session-wide orphan scan was inappropriate, even with exact environment parsing: retained Move source cleanup can run after its destination is active, and two worker generations can share a session ID and host while having different roots. The existing environment regression explicitly models that placement. Harness-specific profile variables are not universally generation-specific. The added marker scan and partially prepared native reader are therefore being removed together. The teardown contract covers the verified worker, its process-group members and captured descendants; it does not newly claim attribution of already-unparented processes outside that forest.

Final ownership review found that PID/startup files are not a sufficient discovery source: startup records are best effort and the existing stop and liveness scripts also discover root-matching process arguments. One shared candidate enumerator now preserves both sources for all three callers. It attributes arguments between matching process-birth reads, propagates failed queries as unknown, and retains a verified dead group leader while live group members remain. Missing/stale breadcrumbs, live children behind a zombie leader and failed fresh per-PID argument queries are covered by the existing OS regression matrix. The final frozen-source run passed all nine affected tests, and the exact helper passed four native Mac smoke modes.

Independent API review found two remaining ownership gaps. Discard initially acknowledged after comparing checkpoint metadata, before any durable disposition; a daemon crash could forget the accepted selection. Also, generic refusal of a Wait request was indistinguishable from a captured operation failure, which could incorrectly restore Move input as a failed draft. These are implementation defects to correct before final validation, not exceptions to the acceptance contract.

## Decision Log

Decision: Separate the cost of suspend execution from the cost of exiting the client. Rationale: moving a wait out of the TUI does not explain or fix a slow checkpoint, and a slow checkpoint must not imply that its initiating terminal stays open. Date: 2026-11-11.

Decision: Preserve accepted work and unsent client data. Do not blanket-abort mutation tasks, replay mutations after a lost acknowledgement, invent a timeout as permission to discard work, or make the daemon depend on an attached TUI. Rationale: one owner must decide when responsibility transfers; request delivery is not necessarily durable acceptance. Date: 2026-11-11.

Decision: Add typed StartSessionLifecycle and WaitSessionLifecycle requests with a LifecycleReceipt containing the exact session and operation IDs; advance daemon protocol 86 to 87. Factor existing synchronous operations through the same start and captured-result watch. Rationale: the current wire reply means completion and cannot safely serve as an early ownership receipt. A closed request enum keeps only supported lifecycle operations admissible. Use the existing lifecycle owner and completed-result FIFO, not a parallel queue or result cache. Date: 2026-11-11.

Decision: A receipt follows the operation's real ownership boundary: Suspend has durable Closing plus lifecycle registration; Restart has its persisted and bound restart intent; Resume transfers its capacity/workspace ownership into the callback; Destroy retains its documented non-durable, bounded handoff exception. Wait is a disposable read observer, not another handoff owner, and exact-ID observation failure must not be presented as failure of the accepted mutation or trigger replay. Rationale: merely spawning a future is not equivalent to transferring responsibility. Date: 2026-11-11.

Decision: Keep environment owner-first and sorted worker-permit acquisition and the transactional Retiring admission freeze. After container quiescence, stop independent remaining worker roots concurrently, join every result/panic, and issue Reclamation only after all writers are stopped. Its scoped exact-target proof permits removal-only cleanup without repeating the stop. Keep child removals serial initially and owner/enclosing removal last. Rationale: this removes the observed multiplicative wait while preserving the structural rule that no working files are deleted before their writers stop. Propagate Sync only through APIs that can reclaim; keep the base executor trait and standalone stop-and-remove helpers intact. Date: 2026-11-11.

Decision: Use the user's teardown model for retirement: kill a raw session's owned harness trees and worker, or kill the enclosing container. Existing container quiescence already uses zero-grace stop plus running-state confirmation. Raw retirement gets an immediate-fence path; ordinary worker-stop callers keep their existing semantics. Capture/freeze verified owned processes, kill them without TERM grace, and confirm non-zombie absence before issuing reclamation authority. Control ancestors and helper probes are excluded before ownership expansion. Unknown unrelated host processes do not become this session's writers or a new refusal gate. Rationale: once checkpoint or explicitly destructive ownership is committed, teardown needs fencing rather than a graceful protocol. Date: 2026-11-11, explicit user steering.

Decision: Ready signals for Move and Resume follow their existing committed MoveOperation and resumed-session writers, respectively. Rationale: in-memory admission and retained upgrade holds protect graceful handoff but cannot reconstruct user selections after a crash. Reuse those existing writes and typed readiness callbacks without a new intent queue or schema. Date: 2026-11-11.

Decision: Remove the added session-wide orphan scan on every platform and the partially implemented Darwin utility. Use the exact-root worker, its process-group members and its descendants as the single ownership source. Rationale: session IDs span Move generations; no universal existing root-specific environment marker exists. Adding another marker, legacy machinery or a native helper to repair this self-added mechanism would expand the task without fixing that ownership error. Separate harness process groups remain covered while they belong to the verified forest. Date: 2026-11-11.

Decision: Represent a captured operation failure explicitly on the lifecycle completion wire; generic refusal or loss of the observer remains observation uncertainty. Rationale: a daemon shutting down before dispatching Wait says nothing about whether its previously accepted Move succeeded. Preserve true failure details without turning that uncertainty into a retry. Date: 2026-11-11.

Decision: Use one shared root candidate enumerator for liveness, ordinary stopping and retirement. Rationale: retirement must preserve existing discovery when breadcrumbs are missing, retain group ownership after a leader exits and distinguish a failed process query from confirmed absence. Reuse the existing root and birth identity contract; do not introduce a marker, service or parallel identity predicate. Date: 2026-11-11.

Decision: Deliver this suspend/TUI work through validation, commit and push only; do not install it. Rationale: the user clarified that the earlier installation instruction did not cover this task. The installed binaries and live daemon remain untouched. Date: 2026-11-11, explicit user steering.

## Context and Orientation

The TUI is the terminal client in `mj-cli/src/dashboard.rs` and its `dashboard/` modules. It owns terminal input and local drafts. The daemon in `mj-controller` owns lifecycle operations such as checkpointing, suspension and worker replacement. `mj-client` defines their control requests and responses. A worker runs the agent and holds its journal and native conversation independently of attached clients.

`mj-cli/src/dashboard/io.rs` renders lifecycle results; `dashboard/io/spawn.rs` and the dashboard task registries coordinate asynchronous requests. The exact exit-drain and acceptance paths must be established from the current code before editing them. `mj-controller/src/controller/lifecycle.rs` and `controller/checkpoint/` implement suspend's checkpoint and source shutdown. Existing daemon lifecycle admission and durable session/operation records must remain the ownership mechanism.

## Validation and Acceptance

A held accepted suspend must continue after its initiating TUI exits; the terminal must not wait for its checkpoint or cleanup to finish. A subsequent client must see the operation in flight and its eventual success or useful failure. The TUI must retain a request until daemon acceptance or an explicit rejection, and must preserve final draft edits before its attachment leaves. Apply the same proof to other command families only when the audit shows they share that boundary. No test may obtain a passing result by canceling the underlying accepted operation or by losing the request before delivery.

For the original session, report the actual phase and measured wait with timestamped evidence. If that cost is necessary checkpoint work, say so; if it is a defect, fix its owner without hiding the failure behind another path or an arbitrary cap.
