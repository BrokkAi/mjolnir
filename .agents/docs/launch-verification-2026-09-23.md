# Launch verification campaign, 2026-09-23

This is an agent-facing runbook for exercising every user-visible surface of `mj` before its public launch, in real terminals, a real browser, and on a real cloud host. It has two purposes at once: **regression** on everything that landed between the close of the last campaign (`.agents/docs/tmux-verification-2026-09-19.md`, 2026-09-19) and the campaign commit — 133 commits, about seventy of them user-visible — and **coverage** of the whole surface as a person who has never used the program would meet it. Unit, render, Playwright and e2e tests cover most of it; this campaign is for what they cannot see.

The campaign is disposable and parallel. Each track is one Opus worker with one isolated lab (or one isolated `--instance`) and, where it needs a terminal, one private tmux server. The coordinator (Fable) prepares the binaries and this document, reads every finding, triages, files issues, dispatches fixes as separate agents after the campaign, and re-verifies. **Workers do not fix anything.** A worker that finds a bug records it and moves on; a finding is only useful when its exact keys, commands, and captures are saved so it can become a regression test.

Two shapes are out of scope by the user's decision: the `morannon-podman` target (SSH + Podman on the user's own host), which the user runs every day and treats as de-risked; and macOS, which cannot run here and is covered by a GitHub issue the user drives on a MacBook (see *Track M*). Also out of scope because nothing here can produce them: a real subscription-quota exhaustion and reset (72dbefee, the 16 h skip in 1d57913e), a Claude safety refusal on demand (30c98758), and the SQLite-busy race (3c668c3d). Record them as not exercised.

## Terms

`mj` is the dashboard binary. The **campaign commit** is `8b7b1120` on `master` in `/home/jonathan/Projects/mjolnir`; the coordinator built three binaries there and copied them to the **campaign root** `/home/jonathan/mj-campaign/launch-2026-09-23/`, outside the repository, because `target/` on this host is a build-cache-managed directory that the cache evicts on its own schedule (it did so during the first run, taking every track's binaries and evidence). Workers use only the copies and never rebuild:

| Binary | Path | SHA-256 (first 8) |
| --- | --- | --- |
| host `mj` | `<root>/bin/debug/mj` | `f78ccc09` |
| host worker | `<root>/bin/debug/mj-worker` | `844e2f63` |
| portable worker | `<root>/bin/x86_64-unknown-linux-musl/debug/mj-worker` | `ec2550bf` |

The layout matters: the daemon finds its worker as a sibling of `mj`, and the portable worker at `../x86_64-unknown-linux-musl/debug/` relative to `mj`'s parent. Evidence lives under `<root>/evidence/`, never under `target/`.

The **prefix** is `ctrl+b`: press it, release, then a second key; `prefix+g` means `ctrl+b` then `g`. A **session** is one agent conversation; a **workspace** is a named group of sessions drawn as a tab across the top of the dashboard. A **target** is where a session's worker and harness run (the built-in `localhost` bare target, a container, or a remote host over SSH). A **profile** is one configured coding agent account (`kind` claude, codex, muse, grok, or kimi). The **fake ACP** is a scripted stand-in for a coding agent that the lab wires in as profile `fake` on target `localhost`; it answers every prompt with `reliability reply: <text>` after a fixed delay, honours cancel, advertises no image support, and **cannot** ask a question, request permission, or fail a turn. The **daemon** is the control plane (`mj daemon-run`, one per instance) that owns the database and the HTTP API; a **worker** is the per-session data-plane process that runs the harness. **Jev** is the hosted turn classifier the worker consults to decide whether a turn is finished, awaiting input, or quota-blocked; it needs the network.

## What is in scope

The full surface, as inventoried on 2026-09-23: the terminal dashboard (panes, Browse pane, dialogs, wizards, Setup, help, palette, composer and slash commands, chat controls), the web viewer (login, cards, new/resume/move, conversation, history paging, turn control, quota and targets pages), the CLI (`mj new/prompt/wait/transcript/diff/export/sessions/suspend/destroy/resume/interrupt-turn/put-file/usage/events/elicitations/respond/api-info/models/set-config/doctor/setup/import/recover/checkpoint/move/login/workspaces/go/app/daemon/acp`) and the bearer `/api/v1` API, daemon lifecycle and automatic upgrade from older releases, SSH targets (session sharding, per-instance control sockets, move, suspend/resume, checkpoint), a Docker target on a real host, the five real harnesses, harness-native and Mjolnir-managed sub-agents, turn review and continuation, quota display, session import from native transcripts, and the public install path and documentation.

## Prepare

Work from `/home/jonathan/Projects/mjolnir`. Every command here opens loopback or Unix sockets, so run outside any restricted sandbox with elevated permissions; an `EPERM` from a sandboxed command is not a product result. Set these in every shell you use and record them at the top of your `notes.md`:

    export MJ_CAMPAIGN=/home/jonathan/mj-campaign/launch-2026-09-23
    export MJ_RELIABILITY_ARTIFACTS=$MJ_CAMPAIGN/evidence
    git rev-parse HEAD
    sha256sum $MJ_CAMPAIGN/bin/debug/mj $MJ_CAMPAIGN/bin/debug/mj-worker $MJ_CAMPAIGN/bin/x86_64-unknown-linux-musl/debug/mj-worker

Never read, write, or create anything under `target/`; if a command of yours would (for example a script that defaults there), stop and record it as a runbook error.

The user's own Mjolnir runs on this host on the **default instance** with a live daemon (`~/.local/share/mjolnir/daemon.json`) and real sessions. Nothing in this campaign may touch it. Every track isolates itself in one of two ways, named on its card:

**A fake-ACP lab** (tracks A–H, K). Prepare it with your assigned seed (with `MJ_RELIABILITY_ARTIFACTS` exported, which puts the artifact directory under the campaign root):

    python3 tests/e2e/prepare-luna-lab.py --seed <SEED> --hel $MJ_CAMPAIGN/bin/debug/mj

It prints `artifacts=<dir>` (under `$MJ_CAMPAIGN/evidence/`), `runtime=<dir>`, and a `source <file>` line. The environment file exports `MJ_CONFIG_DIR` and `MJ_DATA_DIR` (disposable config and state), `MJ_CHAOS_ISOLATED=1`, `MJ_LUNA_ARTIFACTS` (your lab's root, where all your evidence goes), `MJ_LUNA_BINARY`, `MJ_LUNA_PORT`, and `MJ_LUNA_FAKE_ACP_DELAY_MS`. The fake answers prompts after that delay, 15 seconds by default; that window is how you see a session in the *working* state. A card that needs many fast turns says so and may prepare a second lab with `--fake-delay-ms 1000`.

**A named instance** (tracks I1, I2, J). `MJ_INSTANCE=launch-<track>` (or `mj --instance launch-<track>`) puts config and data under `~/.config/mjolnir/instances/launch-<track>/` and `~/.local/share/mjolnir/instances/launch-<track>/`, both empty at first. The daemon, database, logs, and SSH control sockets are all per instance. Create the config directory, write a `config.toml` as your card says, and export `MJ_INSTANCE` in every shell you use. The config must begin with `version = 12`, and it must set `[phone] enabled = true` and `bind = "127.0.0.1:<port>"` with the port from your card — without it the instance tries the default viewer port, which the user's live daemon holds, and every CLI command fails with "Port 3765 is already in use" (finding I1-2 from the first run). Evidence for instance tracks goes under `$MJ_CAMPAIGN/evidence/<track>/`; create it first. Never run `mj recover … --all-instances`, and never run any `mj` command without `MJ_INSTANCE` set in that shell. `mj` is always `$MJ_CAMPAIGN/bin/debug/mj`.

**Real accounts.** Tracks I1, I2 and J use the user's real profiles. Copy only the `[profiles.claude]`, `[profiles.codex]`, `[profiles.muse]`, `[profiles.grok]`, `[profiles.kimi]` blocks from `~/.config/mjolnir/config.toml` into your instance config, verbatim, nothing else (where a card says `[subagents.eligible_profiles]`, write `claude = true` under it rather than copying the user's list, which names profiles you do not have) — the other profiles carry API keys for third-party routers and are not needed. Never copy a config file, token, cookie, or login URL into evidence; captures that show a login code must have the code redacted. Keep prompts short: one sentence, no long agentic tasks except where a mission needs a background task, and stop a session as soon as its mission is done. Every real session's project directory is a scratch repository you create under your evidence root (`git init`, three small commits), never one of the user's projects.

**tmux.** Start a private server named for your track, with a dashboard window sized 140×40 and a second window as your shell. The server name must be unique to you and must never be the user's own server:

    tmux -L mjl-<track> -f /dev/null new-session -d -s v -n mj -x 140 -y 40
    tmux -L mjl-<track> new-window -d -t v -n shell
    tmux -L mjl-<track> send-keys -t v:mj "source '<artifacts>/luna-env.sh'; exec \"\$MJ_LUNA_BINARY\"" Enter

(Instance tracks replace the `source` with `export MJ_INSTANCE=launch-<track>; exec $MJ_CAMPAIGN/bin/debug/mj`.) Drive it only through `tmux -L mjl-<track> send-keys -t v:mj ...` and read it only through `tmux -L mjl-<track> capture-pane -t v:mj -p`. `send-keys C-b g` reaches `mj` as the prefix chord even though tmux itself uses `ctrl+b`; because `mj` runs inside tmux with tmux's default prefix, the dashboard is entitled to show its inside-tmux collision notice on first launch. Send text with `send-keys -l 'text'` and Enter as a separate `send-keys Enter`. Leave about half a second between `C-b` and the second key; `send-keys ';'` never arrives (tmux eats it), so send `prefix+;` as `send-keys -H 3b`. A bracketed paste is `send-keys -H 1b 5b 32 30 30 7e` … `send-keys -H 1b 5b 32 30 31 7e` around the text bytes; an empty bracketed paste is the two sequences back to back. After any key that changes the screen, wait briefly (`sleep 0.3`) before capturing; after a prompt, wait for the fake delay. `prefix+q` exits the process rather than detaching, so the window that `exec`ed the dashboard closes with it. Put helper scripts under your own evidence directory, never in a shared path.

**Sessions in a fake lab.** The dashboard opens on an empty workspace. Create sessions with `n` in the Sessions pane (or `prefix+c`) and expect **four** steps — profile (`fake`), target (`localhost`), project directory (the lab's `project` path printed by the preparer), and a review — each accepted with Enter; the wizard never asks for a title, so rename afterwards with `prefix+shift+t`. The project-directory field remembers the last path, so clear it before typing. `prefix+shift+n` opens the workspace manager; `prefix+n`/`prefix+p` move between workspace tabs; `prefix+1`..`9` jump. Send a prompt by focusing the composer (`Tab` until the Prompt box has focus), typing with `send-keys -l`, then Enter. Session states: *working* is the delay window after a prompt; *done (unread)* is a reply that landed while you were elsewhere; *idle* is a read reply; *failed* is reachable only by killing the session's fake adapter or worker by exact PID (find it by `MJ_DATA_DIR` in `/proc/<pid>/environ`), after which the controller restarts the worker and the warning counts as unread — that is expected, and it is the only failure the lab can produce; *blocked / awaiting input* is **not reachable** with the fake (real-harness tracks cover it).

## Evidence standard

Write everything beneath your evidence root (`$MJ_LUNA_ARTIFACTS/<track>/` for lab tracks; `$MJ_CAMPAIGN/evidence/<track>/` for instance tracks). Keep a `notes.md` that records, per mission, the wall-clock time, every key sent as the exact `send-keys` argument (or the exact command line, or the exact Playwright action), what you expected, what you saw, and the capture file name. Save terminal captures with `capture-pane -p > NNN-<label>.txt`, numbered in order; save browser evidence as accessibility snapshots and console/network summaries, with a screenshot only for an inherently visual question. Capture before and after every assertion, not only on failure.

A **finding** is a numbered entry `<track>-<n>` in `findings.md` with: a one-line title; the exact reproduction from a fresh dashboard, shell, or browser; the capture that shows the wrong state and the one just before it; what the correct behavior is and which commit, document, or help text promises it; and a severity — *blocks* (a person cannot complete the task), *wrong* (the task completes but the screen lies or a key does the wrong thing), or *rough* (works, but a label, hint, alignment, or timing is off). Add a fourth kind for this campaign: *docs* (the product is right but the documentation, help overlay, `--help` text, or first-run guidance says otherwise, or says nothing where a new user needs it). Record a finding before doing anything else, and do not attempt a fix or a workaround; if the dashboard is wedged, note it, restart it, and continue.

When a mission passes, say so in `notes.md` with the capture that proves it. "It seemed fine" is not a result. Finish `notes.md` with a table of missions and outcomes (`pass`, `finding <id>`, `not exercised: <reason>`), and end the run with the cleanup below.
