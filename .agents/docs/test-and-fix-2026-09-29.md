# Test-and-fix campaign, 2026-09-29

This is an agent-facing runbook for a regression and coverage pass over `mj` after the 132 commits that landed between the close of the launch campaign (`.agents/docs/launch-verification-2026-09-23.md`, 2026-09-26, `59a58d62`) and the campaign commit. It follows the same shape: the coordinator (Fable) prepares binaries and this document, writes one mission card per track, reads every finding, triages, dispatches fixes as separate agents in isolated worktrees, cherry-picks onto `master`, validates, and re-verifies on fresh labs. **Workers do not fix anything.** A worker that finds a bug records it and moves on.

Differences from the launch campaign, set by the user on 2026-09-29:

- Test workers and straightforward fixes run on **Sonnet**; involved fixes run on **Opus**. The standing cap of three Opus subagents at once still applies.
- Live-model tracks use **Claude Sonnet 5.5** (`claude-sonnet-5-5`) and **Codex Luna** (`gpt-5.6-luna`) on a profile that still has quota. Grok is tested lightly (one prompt, interrupt, suspend, resume); feature parity between the Grok build and Claude/Codex is not a goal.
- When a fix is larger than a local correction, or a finding's right behavior is unclear, the coordinator asks the user instead of guessing.
- No EC2 or SSH track this time: nothing in the range changed the SSH or EC2 paths except macOS-only work (`221e1343`, `6fc2ed80`), which cannot run here. `morannon-podman` stays de-risked by daily use. macOS stays on issue #1135.

## Terms

`mj` is the dashboard binary. The **campaign commit** is the `master` tip the coordinator built from (recorded under *Build* below). The **campaign root** is `/home/jonathan/mj-campaign/tf-2026-09-29/`, outside the repository, because `target/` is managed by the mbx build cache and can be evicted at any time. Workers use only the copies under the root and never rebuild:

| Binary | Path |
| --- | --- |
| host `mj` | `<root>/bin/debug/mj` |
| host worker | `<root>/bin/debug/mj-worker` |
| portable worker | `<root>/bin/x86_64-unknown-linux-musl/debug/mj-worker` |

`bin/debug/` and the musl `debug/` each hold an empty `.fingerprint` directory on purpose: since `f7272bb0` a binary under a directory with `.fingerprint` refuses to start, replace, stop, or migrate the **default instance**, so a worker that forgets `--instance` or a lab environment gets a refusal instead of taking over the user's live daemon. Treat that refusal as a runbook error in your own notes, not as a product finding.

The rest of the vocabulary is unchanged from the launch runbook's *Terms*: prefix (`ctrl+b`), session, workspace, target, profile, fake ACP, daemon, worker, Jev. Read that section once.

New terms for this range. A **delegation policy** is the per-session Subagents choice a Claude or Codex parent gets in the new-session wizard and in `mj new --subagents`: `native` (the harness's own agents), `all-models` (Mjolnir children on any eligible profile and model), `single-model` (Mjolnir children fixed to one model and effort, `--subagent-model` required), `none`. A **startup step** is a durable record of a session's first prompt or a sub-agent spawn that must survive a daemon restart exactly once; it is the one piece of durable state the concurrency sweep kept (`7029361e`). A **secret reference** is `{ from_secret = "NAME" }` or `{ from_env = "NAME" }` in a profile's or container's `environment` table, resolved from `secrets.toml` beside `config.toml` or from the daemon's environment (`6f89e55f`).

## Evidence standard

Write everything beneath your evidence root (`$MJ_LUNA_ARTIFACTS/<track>/` for lab tracks; `$MJ_CAMPAIGN/evidence/<track>/` for instance tracks). Keep a `notes.md` that records, per mission, the wall-clock time, every key sent as the exact `send-keys` argument (or the exact command line, or the exact Playwright action), what you expected, what you saw, and the capture file name. Save terminal captures with `capture-pane -p > NNN-<label>.txt`, numbered in order; save browser evidence as accessibility snapshots and console/network summaries, with a screenshot only for an inherently visual question. Capture before and after every assertion, not only on failure.

A **finding** is a numbered entry `<track>-<n>` in `findings.md` with: a one-line title; the exact reproduction from a fresh dashboard, shell, or browser; the capture that shows the wrong state and the one just before it; what the correct behavior is and which commit, document, or help text promises it; and a severity: *blocks* (a person cannot complete the task), *wrong* (the task completes but the screen lies or a key does the wrong thing), *rough* (works, but a label, hint, alignment, or timing is off), or *docs* (the product is right but the documentation, help overlay, `--help` text, or first-run guidance says otherwise). Record a finding before doing anything else, and do not attempt a fix or a workaround; if the dashboard is wedged, note it, restart it, and continue. The harness sometimes refuses a `findings.md` write; if so, return the findings as text in your final message and the coordinator writes the file.

When a mission passes, say so in `notes.md` with the capture that proves it. "It seemed fine" is not a result. Finish `notes.md` with a table of missions and outcomes (`pass`, `finding <id>`, `not exercised: <reason>`), and end the run with the cleanup below. Your final message to the coordinator is the table, the findings, the runbook errors you hit, and the cleanup record.
